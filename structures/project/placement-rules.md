# 文件归属与整理计划规则

本页约束新建位置，不授权搬动已有材料。先判断材料职责，再判断是否当前使用，最后选择目录；“旧”“待清理”“临时”是状态，不能单独决定顶层位置。

## 1. 根目录只放已登记的职责入口

| 根 | 默认入口与职责区 | 不应随手新增 |
|---|---|---|
| 代码仓根 | AGENTS、README、ignore、项目实际构建／环境配置，docs、既有代码与配置目录 | 散落的整理计划、日报、全局 archive、backup、日期待清理桶 |
| docs 根 | README、PROJECT、plans；确有共享材料时 shared | 零散 PLAN、项目整理计划_日期.md、第二套进度文件、默认 decisions 或 legacy |
| 数据盘项目根 | README、naming、data、results；旧布局以映射为准 | _runs_archive、混装数据／文档／运行的 archive 或待清理桶 |
| 结果根 | README、既有 registry、runs；确有归档需求时 archive | 以 plan 名另建结果所有权目录 |

这些是默认职责，不是禁止既有 paper、业务目录或必要语言配置。新增职责无法归入已登记区域时，先在整理方案说明用途、消费者、生命周期、维护责任及为何需要独立位置；有授权后更新 AGENTS 和 PROJECT。不要为了落一个文件先造一套新目录。

项目规模、存储和访问边界可要求多个结果根；每个结果根独立登记。不强求全盘只有一个 results，也不因数据是多模态就把所有结果塞入 fnirs/results。

## 2. 路径归属表

| 材料 | 当前内容落点 | 历史／退出使用后的落点 |
|---|---|---|
| 项目整理方案 | docs/plans/structure-adoption/PLAN.md，或复用现有整理计划 | 该计划 backup；整个计划完成后原位保留 |
| 研究方案、设计、实施步骤 | 所属计划 PLAN、DESIGN、IMPLEMENTATION | 同计划 backup 或已保存的 jj／Git 历史 |
| 任务状态、事件 | 所属 TASK、LOG | 保留日志历史，按需分年，不挪到全局 archive |
| 重要决定，包括跨计划整理决定 | 主责计划 decisions，其他入口引用 | 原位标被替代，并链接后继 |
| 外部资料、需求、厂商材料、阅读笔记 | 计划 references；真正共享时 docs/shared | 归属不变，记录版本；大文件留已登记材料位置并引用 |
| 自己计算得到的结果总结、算法尝试结论 | 计划 FINDINGS 或 findings | 保留证据版本与适用范围，不伪装成外部参考资料 |
| 生成的演示报告、预测、图表、模型 | 结果根的 run 产物 | 需要冷归档时进入结果根 archive |
| 小型人工测试样例／固定预期输出 | code/tests/fixtures；已有布局先映射 | 由版本控制保留，遵守大小与隐私要求 |
| 探索性 notebook | code/notebooks；有内容时创建 | 仍归代码区，生成的正式产物保存在 run |
| 原始数据 | 已登记 raw 区，只读 | 保存策略单独约定，不作为“旧文件”清理 |
| 共享派生数据 | 已登记 interim 数据产品版本 | 仍在数据职责区，保留来源与消费者 |
| 未验收新数据 | data/incoming 或模态内已登记暂存区 | 验收后按来源转入 raw／interim，转移另需授权 |
| 待隔离材料 | 所属职责区内 quarantine/<批次>/，按需 | manifest 说明原路径、原因、核验和恢复；不混装 |

业务“备份”与历史归档不同：plan/backup 是方案历史，results/archive 是运行冷归档，独立介质备份提供故障恢复。归档不等于已备份，隔离不等于已授权删除。

## 3. 结果归档必须留在结果职责区

```text
<结果根>/
├── README.md
├── registry.*
├── runs/<run_id>/
└── archive/                     # 仅确有冷归档需求时创建
    └── <归档批次或明确分组>/
        ├── manifest.md
        └── <run_id>/            # 运行内容和身份保持可追溯
```

默认完成 run 原位保留，退出活跃使用可先登记状态。仅在明确空间／保存需求且获迁移授权时移动。归档跨盘的目标是 `<目标数据盘>/<登记结果根>/archive/...`，例如 eyedata/results/archive/...；不得落在 eyedata/archive 或 eyedata/_runs_archive。

直接复制到最终归档位置通常优于“先本地搬进 archive，再跨盘搬一次”。只有本地分组有独立验证目的时才分两段，说明每步的输入、核验、切换与恢复。分组按稳定来源／批次组织，不改变 run_id，不依据前缀或日期断言无人使用。

移前核对运行作业、论文采用、代码、台账及下游引用；受引用的 run 不代表永远不能归档，但必须保证引用可解析。复制后核对逐文件清单、大小与内容哈希；只比较目录数和总字节数不足以确认一致。记录新旧绝对路径、范围身份、run_id、核验及恢复方法。更新消费者与实际台账路径后才切换权威位置；现有工具不自动修复路径或搬迁记录。

通过校验不自动授权删除源目录；文件清理须处于明确授权范围。未经核实的失败 run、空文件、压缩包不能凭名字归为冗余。

## 4. “先映射”是接入阶段，不是最终架构

旧项目可暂留散落文档，但须列原位置、语义归属、当前权威性、引用者和后续处置条件。用户只要求接入时停在映射；用户授权整理时按清单分批归位。不能把“旧项目先映射”解读为永远保持多套活跃计划，也不能据此自动搬迁。

不能归属的历史文档先原地登记待分类，不自动建 docs/legacy 或 docs/archive 混装。确需跨计划历史材料库时，明确其材料边界、索引和为何不能归入既有计划；这属于有理由的扩展，不是默认第四层目录。

## 5. 整理计划的最小可执行要求

使用 [整理计划模板](../../assets/templates/structure-adoption-plan.md)。写前先读 PROJECT、AGENTS 与实际路径，仅查看目录不足以认定来源或版本。

1. 明确授权范围：只读设计、文档修改、迁移、清理分别标实际授权。
2. 把现状、目标、已执行分开；目标树每个标记都有核对日期和证据，不把聊天意见当已落盘事实。
3. 每组材料必须有唯一语义归属、源／目标绝对路径、动作、理由、消费者、检查和恢复方案。
4. 计划边界按可独立验收目标判断。不同版本不拆成新计划；同一方向不强行合成一个计划；历史闭合工作可原地索引，不机械生成三件空文档。
5. PLAN 只保存整理方案；TASK 是当前执行状态；LOG 记录已发生事件。未知状态标待核对，不凭历史叙述补完成证据。
6. 目录树、映射表、步骤三者必须一致。逐项检查无根级混装 archive，无默认 docs/decisions，研究发现与运行实体没有塞进 references。
7. 检查大小、隐私、活跃运行、台账碰撞、引用与回滚；没有现场验证不能宣称目录或 schema 校验已覆盖这些要求。

## 6. 临时文件：按用途归属，不新建顶层杂物目录

禁止 agent 自动在代码仓根、docs 根或数据盘项目根新建 scratch/、tmp/、temp/ 及其他同义的通用临时目录。临时是生命周期，不是独立的顶层职责。ignore 条目不是创建授权。

| 用途 | 位置与处理 |
|---|---|
| 某次运行的临时计算文件、检查点暂存 | <结果根>/runs/<run_id>/tmp/，有内容才创建；恢复依赖未解除前保留 |
| 多次运行复用的中间数据 | 已登记 data/interim 或对应模态 interim 的版本化数据产品，记录生产来源与消费者 |
| 一次性调试、预览、试验文件 | 系统临时目录内由 tempfile／mktemp 等创建唯一子目录，不使用固定共享路径 |
| 可维护的脚本、运行入口与编排器 | 项目已登记的代码目录；临时用途不改变代码职责 |
| 需要保存、引用或正式交付的调试结果 | 及时归入所属 run 的产物目录并登记来源，不长期依赖系统临时目录 |

项目 IO 路径仍通过 path_manager 解析为绝对路径；系统临时目录以运行环境实际配置为准，不硬编码 /tmp。第三方工具或集群要求专用 scratch 时，使用已有授权的外部临时存储，按 run 隔离并记录实际路径、容量与生命周期；不据此创建仓根 scratch。科学输入、日志、来源证据和最终产物不能只保存在可能自动清理的空间。

已有 scratch／tmp／temp 先登记来源、内容与活跃进程依赖，不自动删除、搬迁或重命名。归位属于另一个需明确范围的整理动作。清理只能覆盖当前任务创建且已确认不再依赖的临时材料，并遵守实际清理授权；不得扫描清空共享临时目录。
