# 项目群、项目与分析主线的统一管理

> 具体项目的目录、plan／LOG／进度／结果记录与周期检查统一执行 [具体项目结构规范](../documents/GUIDE.md)。本页只解释项目群关系、共享依赖和接入原则；不再授权各项目临时自定记录体系。

## 适用范围与依据

research-project 管整个科研项目的组织、架构、状态和交接，分析模板只是其中一部分。先识别范围，再进入对应专项 skill。已有项目先登记映射，目录迁移作为后续独立任务。

本规则承接旧规范的“仓管代码、盘管数据、超算管执行、发布保留固定交付”、多子项目独立当前状态、共享工具引用不拷贝、项目类型按需裁剪等思考。旧规则原文快照见 `<reference-archive>/…`（本地归档，公开版不含该快照）。不恢复其中已被当前决定替代的固定工具禁用、自动清理或旧收尾流程。

## 管理层级：按责任和生命周期区分

| 层级 | 管理内容 | 何时需要 |
|---|---|---|
| 项目群／工作区 | 子项目地图、共同资源、跨项目依赖、里程碑与阻塞 | 多个独立研究或仓库需要共同协调时 |
| 项目 | 研究目的、交付、代码与数据位置、负责人、环境、当前安排 | 有可独立说明的目标和生命周期时 |
| 主线／子项目 | 具体目标、plan、入口、配置、结果根、进度与判断 | 同项目内需独立推进、运行或交接时 |
| 方案与运行 | 方法组件、固定输入、实际执行、检查和产物 | 执行分析时 |

小项目可直接“项目→方案与运行”，不创建空的项目群和子项目层。大项目可以包含独立仓库，也可以一个仓内多主线；目录嵌套、仓库边界与研究层级不要求一一对应。论文和 run 也不自动升级为子项目。

拆分依据是目标、责任、生命周期、权限或依赖边界。分类与回归有不同目标可各有 plan；换算法、特征或参数通常仍是同一问题下的方案。跨项目协作通过明确的输入产品和版本引用，不复制整个工程。

## 每层只维护自己的事实

项目群地图记录每个项目的稳定名称／键、父级、类型、目的、状态、入口、代码根、数据根与关联资源；未知项标待核对。父级聚合状态并标核对时间，不复制子项目全部待办和结果。

项目记录主线地图、当前工作、交付与共同问题。每个方向可包含多份独立 plan，plan 可归属多个方向。PROJECT.md 内计划入口统一登记；每份 plan 独立维护任务、执行引用与判读状态，具体结构按正式规范。并行任务结束只更新所属主线，不能抢占全仓“当前”。

运行独立于计划，以“结果范围＋run_id”定位；计划通过引用使用。同一 registry 内 run_id 唯一，不同范围的同名记录不能直接拼接。实际数据盘布局见 [数据盘架构](../data/GUIDE.md)，结果目录见 [结果架构](../results/GUIDE.md)。

共享材料独立记录生产者、材料身份、含义与单位、允许用途、版本、访问位置及消费者。父级不能把不同队列的同名指标自动当作同一数据产品；主体身份映射只留受控 naming/。

## 物理结构与代码架构

| 职责 | 新项目推荐位置 | 老项目接入方式 |
|---|---|---|
| 项目群地图 | 根目录一份轻量地图／README | 原地建立索引，不把父目录强行初始化成总仓 |
| 操作入口与状态 | 项目入口＋机器可读状态 | 复用 AGENTS.md、WORKSPACE.toml 等已有入口 |
| 活代码 | code/ 或既有包目录 | 记录真实入口与模块边界，不因命名不同重建 |
| 配置 | configs/ | 复用现有 TOML／JSON／YAML，避免重复含义 |
| 计划、日志、进度、结果模板、判断与采用 | docs/ 下固定职责，详见具体项目结构规范 | PROJECT.md 登记唯一权威路径；由动作模块 按触发更新并周期核查 |
| 原始／中间／结果实体 | 外部数据根，按职责和 run 隔离 | 兼容 raw、0_raw、interim、results、outputs/runs 的已有映射 |
| 共享基础程序 | 统一安装位置或版本化包 | 项目引用版本与参数，不复制脚本母本 |
| 机器与超算 | 路径映射、资源配置、执行适配 | 科学参数与机器参数分开；实测能力再标支持 |

新项目先问代码／科研类型及是否初始化 jj，按既有 project-init 与项目规则执行；不用本 skill 自动覆盖 VCS／DVC 选择。分析、文献、工具、材料项目可共享管理字段，保留自己的结构；不要给文献综述强加信号预处理树，也不要给工具包强加医院数据目录。

代码按入口、领域模块、方法策略与公共基础功能组织。入口负责装配；领域模块表达计算；策略表达并存方法；公共层负责路径、配置和记录等稳定机械能力。Python／R／MATLAB 保留各自合理包结构，跨语言以明确输入输出和环境连接。

方法变体不当版本目录；旧 analysis_v1 等目录先核对调用、产物和论文引用，不按名字判断可删除。共享算法前核对科学含义、单位、拟合范围及代表性输入上的行为。活代码不得依赖归档代码；先断依赖再讨论冻结或归档。

## 什么时候做什么

1. 接入：只读检查入口、仓库边界、顶层结构、路径配置和现有主线。先产出项目地图与证据，不读个体原始数据来猜架构。
2. 规划：列目标和交付、子项目分工、依赖、里程碑、资源预算及关键风险；主线待办引用所属问题，安排先考虑证据可信度和前置条件。
3. 结构变更：列旧位置→目标职责／位置、引用影响、数据身份、验证与回滚路径。用户授权的迁移范围内分批实施，禁止先大搬家再修引用。
4. 开发与执行：交 [code](../../modules/code/GUIDE.md)／[run](../../modules/run/GUIDE.md)，沿用本层归属；共享模块变更检查全部已登记消费者，保留未知影响边界。
5. 汇总与判读：交 [interpret](../../modules/interpret/GUIDE.md)；项目群汇总里程碑与阻塞，不将不同主线指标合成总排行榜。
6. 冻结与交接：交 [release](../../modules/release/GUIDE.md)；独立记录代码、研究判断、结果验收与备份状态。已冻结材料仍能定位；交接包含入口、依赖、未决问题与下一步。

架构体检关注：入口是否唯一可定位、主线状态是否互相覆盖、代码是否混进数据盘、共享代码是否复制漂移、输入产品是否有来源、结果归属是否明确、活动代码是否依赖归档、备份与四口检查是否落实。发现问题先分轻重和影响范围，不把整个项目判成“不合规必须重建”。

## 验收与边界

小项目不依赖项目群组件即可执行；多仓项目群能定位每个子项目；单仓多主线互不覆盖当前状态；同名 run 跨项目不冲突；换机器只改位置映射；共享产品变更可定位消费者；历史路径仍可追溯。文档模板目前提供人工管理方式，未实现自动项目群调度器或全盘架构扫描器。

本地接入对象的已知事实与待核对项见 `<reference-archive>/…`（本地现场映射，公开版不含该清单）。本轮仅完善 skill，未迁移它们。

## 当前文档层级

默认 docs/PROJECT.md 为项目入口，docs/plans/{plan_id}/ 内维护 PLAN、TASK、LOG；发现、参考和决定按需创建。任务增长后再拆文件。完整职责以 文档结构模块修订 4 为准，旧项目保留映射。

涉及新目录、历史归档与迁移时，以 [文件归属规则](placement-rules.md) 核对位置和授权；整理计划须明确现状、目标、唯一归属、引用及验证。
