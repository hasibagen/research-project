# 代码与配置结构

本模块约束源码、配置、环境和验证材料。实现过程使用 [code 动作](../../modules/code/GUIDE.md)，执行过程使用 [run 动作](../../modules/run/GUIDE.md)。不要求为科研脚本建立企业应用框架。

## 默认架构

```text
<代码仓绝对路径>/
├── code/
│   ├── README.md
│   ├── run_analysis.py        # 示例入口：装配配置、路径、计算、记录
│   ├── preprocessing/        # 按实际科学步骤组织
│   ├── statistics/            # 模型、统计检验
│   ├── ml/                    # 仅有机器学习时需要
│   ├── tests/
│   │   └── fixtures/          # 小型合成输入与已知期望
│   ├── notebooks/             # 探索时按需
│   └── utils/
│       ├── path_manager.py    # 解析所有项目 IO 绝对路径
│       └── config.py          # 有效配置加载与验证
├── configs/
│   ├── analysis.yaml          # 科学参数、输入版本、随机性
│   └── machine.yaml           # 数据／结果根、资源、执行环境
└── environment.yml            # 或项目已有环境／锁文件
```

仅创建使用的模块；单个脚本可以先保留一个入口和路径工具。已有 src 包、R 包或 MATLAB 目录不自动改名。配置格式沿用已有 JSON/TOML/YAML，不能多份独立维护同义参数。

## 依赖与接口

入口装配计算模块；计算模块接收数据和显式参数；公共层处理路径、配置与记录，不反向导入某个具体计划或模型。编排器描述计算依赖，不承载科学算法。代码不得靠 docs/plans 的目录名决定算法行为。

每个实际计算模块在 code README 的独立章节或自己的 README 写明：输入形状与列、单位、样本粒度、拟合范围、输出、失败情况、上游下游，以及一个代表性调用。Python/R/MATLAB 之间以明确定义的文件或函数接口连接，不猜 API。

## 放置与变更约束

- tests 和 notebooks 属于代码区，默认分别放在 code/tests 和 code/notebooks，不在代码仓根另建同级目录。已有位置先登记，迁移按授权处理。
- 可维护入口、批处理、编排脚本归代码区；不能因“临时运行”散落到数据盘或 results。
- 算法变体作为方法选择或模块实现，参数变化归配置，不建 analysis_v2/final 代码副本。
- 全部 IO 经 path_manager 返回绝对路径；创建输出目录也通过该工具。算法内不硬编码机器目录，不写 raw。
- 科学配置与机器位置分开；展开默认值与命令行覆盖后保存 config_used。改配置立即核对语法及实际生效值。
- 插补、标准化、特征筛选和调参须保留训练范围，不能为了复用把拟合放到全样本共享预处理。
- code/notebooks 用于探索；可复跑的核心计算进入代码模块，生成的图表和模型进入对应 run。
- 共享代码使用版本化包或登记的唯一源码位置；修改后查消费者。运行溯源保存代码提交和必要未提交补丁，旧结果保留。

## 项目内架构说明与样例

code README 是本区入口，包含真实代码树、依赖方向、配置优先级、环境恢复、运行和验证样例。configs 和 tests 较小时在此分节说明；形成独立接口后再各设 README。已有包文档满足这些内容时直接引用。

新建模块时同时补其接口和样例，修改模块边界或配置键时同步。示例中未核实的命令标“未执行”，不能杜撰现有脚本参数。

## 检查

核对路径解析、配置覆盖、代表性输入输出、单位、样本数和科学拟合边界；执行与改动相称的既有测试或冒烟验证。不要用“脚本能 import”替代科学行为检查；也不为纯文字修改强制运行全分析。

完整的模块与接口示例见 [EXAMPLE](EXAMPLE.md)。环境、运行、记录接口以项目源码和 [执行协议](../../docs/snakemake-workflow.md) 为准。
