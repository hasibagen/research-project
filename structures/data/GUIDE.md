# 数据盘架构：数据、结果与身份信息

本页是结构层权威正文；整体关系见 [项目结构](../project/GUIDE.md)，本区实例见 [EXAMPLE](EXAMPLE.md)。

## 新项目默认结构

数据盘项目根包含数据与结果两个独立职责区；结果不归某个计划所有。单模态项目默认省略模态层，直接使用 data/raw 与 data/interim/<dataset_id>/<version>；在 README 写明模态即可，不为单一模态增加一层目录。多模态数据按模态区分，运行统一保留来源，跨模态分析不用勉强归入其中一种模态。

单模态的数据区：

```text
<数据盘项目根>/data/
├── raw/                          # 原始数据；只读
└── interim/                      # 可复用数据产品；按需
    └── <dataset_id>/<version>/
```

多模态的完整布局示例：

```text
<数据盘项目根>/
├── README.md                      # 实际路径、数据来源、结果入口与访问说明
├── naming/                        # 姓名与研究 ID 的受控映射
├── data/
│   ├── fnirs/
│   │   ├── raw/                   # 原始采集文件；只读
│   │   └── interim/               # 版本化的可复用整理数据；按需
│   ├── eeg/
│   │   ├── raw/
│   │   └── interim/
│   ├── beh/
│   │   ├── raw/
│   │   └── interim/
│   └── scale/
│       ├── raw/                   # 原始量表与临床材料；按实际敏感性控制
│       └── interim/
└── results/
    ├── README.md                  # run 组织与查找说明
    ├── registry.json              # 示例；已有 CSV 台账不强改
    └── runs/<run_id>/             # 所有模态、跨模态执行均可使用
```

只创建当前需要的模态与目录。results 是此数据盘的结果根，对应 [结果架构](../results/GUIDE.md) 中的 `<结果根>`；已有 result、results 或 outputs 名称通过 PROJECT 映射，不强制改名。数据根与结果根可以在不同磁盘，实际 IO 经 path_manager 解析为绝对路径。

## 数据与结果怎样划界

- 原始采集、原始行为、原始量表保存在 raw，只读，不覆盖修订。后续更正以新批次或新版本记录来源。
- 一次执行产生的清洗数据、特征表、预测或模型先属于该 run 的产物；临时计算文件放该 run 的 tmp/；可复用数据另按下条登记。禁止自动新建数据盘或仓根 scratch／tmp／temp，外部临时存储例外见文件归属规则。
- 需要被多个后续运行长期复用的数据，可登记为 interim 下的版本化数据产品：单模态用 data/interim/<dataset_id>/<version>/，多模态用 data/<模态>/interim/<dataset_id>/<version>/。记录生产 run、输入版本、配置、单位、样本身份、访问条件与校验信息。
- run 产物升级为共享数据产品时明确唯一权威位置。需要移动或复制须另获相应授权，并更新引用；必要副本记录来源和校验，不维护两个可独立修改的版本。
- 数据字典、来源和字段解释可以随数据集保存 README；分析方案和科学解释放计划文档。跨模态对齐数据若实际需要，可新增 data/multimodal/interim，不预建空目录。
- naming 是受控身份映射；脱敏 ID 不代表所有数据都无隐私风险。按实际授权管理 raw、临床信息、映射及其副本，naming 不入代码仓、不上传超算。

## 旧项目：先映射，再讨论迁移

已有“模态下面同时放数据与 results”的布局可以继续使用。登记 data_role、实际绝对路径、模态、版本／批次、来源、访问约束和消费者，而不是先搬大文件。

下面仅说明用户提供的目录可能怎样映射，并非已核查磁盘：

| 既有相对位置 | 建议登记职责 | 接入动作 |
|---|---|---|
| fnirs/0_raw、fnirs/0_bikeming | fNIRS 原始数据 | 原地只读登记 |
| fnirs/0_variant | 通道重排的中间数据 | 核对来源和报告链输入约定，原地登记 |
| fnirs/0_beh | 原始行为数据 | 原地登记；不能仅凭名字判断与整理版重复 |
| fnirs/0_beh_organized | 整理行为数据 | 登记转换来源与未匹配项 |
| eeg/脑电 | EEG 原始数据 | 原地只读登记，考虑文件名中的身份信息 |
| beh、scale | 行为／量表资料，原始或派生待核对 | 查来源后定角色，不猜测 |
| fnirs/new | 未验收批次／暂存材料 | 核对是否已经并库，不自动删除 |
| fnirs/interim | 共享中间数据 | 登记版本、生产来源和消费者 |
| fnirs/results、eeg/results | 两个既有结果根／执行范围 | 各自保留台账，完整身份含范围与 run_id |
| 待清理_<日期> | 隔离区 | 保留原路径、原因、校验与恢复方法 |

已有模态结果根不要求合并；新跨模态运行可以使用独立结果根，通过 PROJECT 与数据盘 README 登记。已有台账不直接拼接，同名 run 必须保留来源范围。正在运行的输入、输出、临时目录和原始材料不参与整理搬迁。

如明确授权迁移：先核对消费者和可用空间，复制后校验文件清单、大小与适当的内容哈希，确认引用和恢复办法，再按授权处置源目录。抽样检查不能证明完整迁移；校验通过也不自动授权删除。

失败 run、空文件、压缩包、__MACOSX 和旧版本不能仅凭名称判定冗余。隔离不等于删除，quarantine 不是常规自动清理机制。历史计划的 backup 是文档历史，不承担 TB 级数据备份；数据另有独立介质副本与保存策略。

## 项目说明文件

使用 [数据盘 README 模板](../../assets/templates/data-root-readme.md) 记录真实布局和映射。PROJECT 登记数据盘入口与权威路径，不再抄一套数据台账。已有项目采用本规范须有明确应用范围；提供项目目录案例只授权理解与设计时，不修改案例项目。

结果根 README 同时提供实际数据布局摘要：单模态／多模态、所含模态、以实际绝对路径为根的目录树、raw／interim 的职责与绝对路径，以及权威数据 README 的绝对路径。这里只保存查找入口，不复制数据版本和消费者台账；具体运行输入以 run 的来源记录为准。获授权变更布局时同步更新相关结果 README。后来增加模态时先登记真实位置与映射，不自动搬迁已有单模态数据。

## 暂存与归档的归属

新建暂存采用 data/incoming 或对应模态区；隔离材料放所属数据／结果职责区的 quarantine，不在数据盘根默认建立综合隔离桶。上表旧“待清理”目录只是历史映射，不授权再新建同类根目录。run 历史归档只进入已登记结果根的 archive；见 [文件归属规则](../project/placement-rules.md)。

## 项目内入口、内部模块与样例

数据盘 README 提供实际数据架构与读取样例；模态区或数据集有独立接口时，由该区 README 说明内部树、字段／单位、生产来源、输入版本、消费方式和检查。单模态简单项目可合写，不能为形式创建空模态层。数据字典与版本记录只保留一份，各入口引用。

完整的单模态、多模态及共享数据产品说明见 [EXAMPLE](EXAMPLE.md)。结果 README 同步提供输入数据架构入口，实际运行输入仍由各 run 固定。
