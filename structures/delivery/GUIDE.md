# 交付材料结构

本模块管理固定采用记录、稿件与独立交付包的关系。选择、核验和外发流程使用 [release 动作](../../modules/release/GUIDE.md)。

## 架构与职责

```text
<代码仓绝对路径>/docs/plans/<plan_id>/
└── DELIVERY.md                # 采用版本、材料清单、来源、检查与限制

<已有稿件绝对路径>/            # 例如项目 paper；有写作需求才创建
├── README.md                  # 稿件结构、构建与采用样例
└── ...                        # 人工维护稿件；图表引用固定 run

<已登记交付包绝对路径>/        # 仅需要独立包时创建
├── README.md                  # 包结构、使用方式、范围与限制
├── manifest.*                 # 真实文件、来源身份、校验与许可
├── ...                        # 本次明确选中的材料
└── ro-crate-metadata.json      # 使用 RO-Crate 导出时才生成
```

不默认新建顶层 releases、audits 或 experiments 来复制结果。已有论文／交付目录登记实际位置。包可以是结果根内交付 run 的 artifacts 子目录或用户明确指定的登记位置；打包产生新计算时保存对应 run 来源。工具要求目标目录不存在时使用新路径。

## 唯一来源与约束

DELIVERY 固定完整结果范围、run_id、具体产物、代码和输入版本；原始结果继续保存在 run。独立包是固定副本，记录来源与校验，不成为第二份可修改结果。更换采用图表时修订 DELIVERY 并保留历史，不能覆盖旧 run 来维持同名链接。

包 README 说明内部树、环境与复跑入口、预期输出、检查范围、数据访问和限制；具体清单在 manifest 维护。论文数字要能回到具体表格和复算入口。多次交付需要多个包时使用清晰版本身份，不以 final_v2 作为来源证明。

采用、打包、上传是不同动作。用户授权准备包不自动授权发布；隐私、许可、备份、独立复算与科学采用按日常规范核对。RO-Crate 元数据有效不等于包可复算或科学有效。

## 检查与样例

从任一交付文件反查来源 run、配置、代码、输入和检查；核对包清单与实际内容，验证链接或受控取回方式。执行过与未执行的复跑分开标明。固定采用和交付结构的填写示例见 [EXAMPLE](EXAMPLE.md)，使用 [DELIVERY 模板](../../assets/templates/release.md)。
