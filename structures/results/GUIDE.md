# 结果目录与 run 架构

本页是结构层权威正文；整体关系见 [项目结构](../project/GUIDE.md)，本区实例见 [EXAMPLE](EXAMPLE.md)。

## 1. run 放在哪里

默认位置为：`<结果根>/runs/<run_id>/`。

结果根是 PROJECT.md 登记的绝对路径。小项目可为 `<项目根>/outputs`，大型分析可为数据盘上的独立目录。已有 `results/` 名称和运行布局继续使用，通过 PROJECT 映射；不因本规范搬动既有数据。未核对结果根时不能默认新建 outputs 和 results 两套；先确认 PROJECT 的实际映射，目录名称不表示结果已退出使用。

目录示例中的占位符须替换为实际路径；执行时所有 IO 经项目 path_manager 解析为绝对路径。文档存于 `docs/plans/<plan_id>/`，run 存于结果根，计划通过完整运行身份和具体产物引用使用结果，不以目录包含关系规定结果归属。

本文件是 skill 的架构规范；它的存在不表示某个项目已经创建了 outputs 或实际 run。只有获授权启动具体分析时才在其结果根建立运行目录。

## 2. 默认结果树

```text
<结果根>/
├── README.md                         # 结果位置、目录说明与查找方式
├── registry.json                     # 当前公共工具使用的运行登记文件
└── runs/
    └── run_20261020_143000_baseline/
        ├── record.json               # 本次运行的结构化记录
        ├── config_used.yaml          # 实际生效配置快照；沿用真实格式
        ├── provenance/               # 输入身份、上游产物、代码与环境证据
        ├── tmp/                      # 本 run 临时计算文件；按需，恢复依赖解除前保留
        ├── logs/                     # 程序输出、作业回执、恢复记录
        ├── tables/                   # 指标、统计与汇总表
        ├── figures/                  # 图表
        ├── predictions/              # 逐样本预测；按需
        ├── labels/                   # 聚类标签；按需
        ├── model_dump/               # 模型或拟合对象；按需
        ├── artifacts/                # 其他产物；按需
        └── CHECKS.md                 # 产物检查结果及证据
```

一个结果根默认作为一个执行范围，run_id 在该范围内唯一。结果根可按实际数据存储或访问边界分设，不默认按计划拆分。跨范围引用须带结果根身份与 run_id。同一秒启动多个运行时增加唯一后缀，不覆盖已有目录。只创建实际使用的产物目录。run 内的路径供记录引用，实体不复制进 docs。

上述 record.json、registry.json 沿用现有工具接口。讨论方案时使用的 RUN.json、registry.csv 是概念示例，默认实现采用这里的名称；不并存两套权威记录。已有 CSV 台账继续按项目映射使用，不自动转换。

## 关系：计划、执行与产物

- plan 定义研究目标与方案，可使用多个 run 的结果。
- run 记录一次实际执行，可产生多个产物，也可服务多个计划；不要求一一绑定计划。
- 产物是特征表、模型、统计表或图等具体文件，可被后续 run 或多个计划复用。

TASK 引用启动或核查的 run；FINDINGS 引用支撑观察的具体产物；下游 run 的 provenance 记录所用上游产物的完整位置、版本或哈希及来源 run。当前工具没有自动维护这些关系，不能假定存在反向依赖索引。

例如，一次 EEG 预处理的产物可同时服务 oddball、分类和回归计划。运行与产物保持独立身份，各计划按问题引用。运行清单用于追溯；可信性、解释与正式采用由检查、FINDINGS 和 DELIVERY 记录，不能由目录名称判断。

## 3. 每类文件负责什么

| 内容 | 保存位置 |
|---|---|
| 项目结果根、环境和机器路径映射 | docs/PROJECT.md |
| 预期结果与整体验收标准 | 对应 PLAN.md |
| 当前任务状态、run 引用与验收证据 | 对应 TASK.md |
| 启动、失败、恢复等关键事件 | 对应 LOG.md |
| 多个 run 的观察、比较、解释与限制 | 对应 FINDINGS.md |
| 本次实际输入、配置、代码、环境、机器、产物和检查 | record.json 及其引用的 provenance、配置和 CHECKS 文件 |
| 本执行范围内已导入的运行记录 | registry.json；是登记快照，不独立手改运行事实 |
| 正式采用哪些版本与产物 | 对应 DELIVERY.md；按需创建 |

输入身份可以是数据版本、清单和校验值；原始数据不复制进 run。代码须记录提交标识，未提交修改须保留可恢复快照或补丁，不能只记提交号。配置使用展开后实际值；环境、随机种子及划分来源按分析需要固定。超算作业保存机器、作业号、提交回执与时间，时间注明时区。

## 4. 运行与恢复规则

- 输入、科学配置或代码发生影响结果的变化，创建新 run；不覆盖旧产物，不用 final_v2 代替执行身份。
- 断点续跑只有在输入、配置、代码身份一致且程序支持恢复时沿用原 run；每次恢复单独保存日志与回执，不覆盖此前失败信息。
- 失败与中断保留实际产物、退出信息和原因；缺失指标不填零。阴性发现不是程序失败。
- 程序成功、产物完整、科学检查、正式采用分别记录。文件存在或退出码为零不等于科学结论有效。
- 跨 run 汇总若生成新的表格或图形，建立汇总 run，并登记全部来源 run 和汇总代码／配置。单纯人工解释写 FINDINGS。
- run 独立保存；多个计划引用同一运行及具体产物，不设计划所有者。计划拆分、合并、取消不改变 run 的身份、位置与历史，不复制成多份可独立修改的结果。
- 完成运行后固定来源与产物；纠正计算错误建立新 run。补充解释和检查保留日期、理由与原记录，不能静默改变已登记事实。
- 大型共用中间数据按项目 data/interim 映射管理，run 记录所用版本。论文采用链接固定产物，需要独立交付包时记录其来源和校验。

## 5. 现有工具的能力边界

公共 schema 和 research_records.py 的接口见 [运行记录说明](../../docs/record-v2.md)。当前 record.json 不支持任意增加 project_id、plan_id、task_id 或准备／运行中等状态字段；计划使用关系和任务关联保存在 PROJECT、TASK、FINDINGS 的引用中，未支持的来源信息作为 provenance 材料列入 artifacts。

运行中状态根据实际作业与日志核对后写 TASK；结束后构造 schema 接受的记录并校验。registry.json 是显式导入的登记文件，不是自动监控服务；它不自动扫描 runs，也不自动更新已登记记录。同身份不同内容会冲突，不能声称记录已修改就会自动同步台账。

调用工具前查看 --help 和实际 schema，明确 --root 等路径参数。新布局以结果根作为默认执行范围，已有执行范围保留映射。全项目查找从 PROJECT 登记的结果根定位各范围 registry；全局 CSV 总索引若将来需要，应由范围记录派生，当前未实现自动生成。

## 6. 结果根的说明文件

创建新的结果根时使用 [结果 README 模板](../../assets/templates/results-readme.md)，填写实际绝对路径、执行范围、结果引用方式、台账格式、运行命名、查找与恢复入口。已有结果根先核对并补充现有说明，不另外制造同职责文件。

结果 README 必须包含“输入数据布局与入口”：注明单模态／多模态和实际模态，展示以实际绝对路径为根的数据目录树，列出 raw／interim 的职责、绝对路径及权威数据说明入口。单模态默认 data/{raw,interim}，多模态默认 data/<模态>/{raw,interim}；旧布局如实填写。此处供 AI 与读者从结果定位数据，不复制数据台账，也不代替各 run 的具体输入版本与来源证据。数据布局获授权变更时同步更新。

本规范说明目录和生命周期；填写结果解释与固定采用见 [结果工作流](../../docs/results-workflow.md)，文档组织见 [文档规范](../documents/GUIDE.md)。

数据与结果同盘的完整布局、已有模态目录映射见 [数据盘架构](../data/GUIDE.md)。结果路径独立于计划，已有结果根可分设。

涉及新目录、历史归档与迁移时，以 [文件归属规则](../project/placement-rules.md) 核对位置和授权；整理计划须明确现状、目标、唯一归属、引用及验证。

运行临时文件仅放本 run 的 tmp/；一次性调试使用系统唯一临时目录。需要保留的证据及时归入 run，不能只存临时区。不自动新建仓根或数据盘根 scratch／tmp／temp，详见 [临时文件规则](../project/placement-rules.md#6-临时文件按用途归属不新建顶层杂物目录)。

## 项目内入口、内部模块与样例

结果 README 说明真实内部树、执行范围、输入数据架构、台账查找、恢复规则及一个具体查找样例。每个 run 通过 record、config_used、provenance、CHECKS 说明内部产物、来源和验证，不强制另写重复 README。新增独立产物格式时说明其字段／单位、来源和使用方式，可放产物旁说明文件并由记录引用。

完整结果入口与单次运行实例见 [EXAMPLE](EXAMPLE.md)。结果规范约束放置和证据；执行、导入及判读流程分别由动作模块承担。
