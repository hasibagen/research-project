# 用研究可复现与协作原则约束管理架构

日期：2026-10-19。来源核对与设计判断见 [哲学审视](turing-way-review.md)。本页是本 skill 的操作原则，不是 The Turing Way 对目录的强制规范。沿用已确定的 project → plan → task 架构。

## 1. 记录服务于研究与接手

衡量管理效果要看能否找到证据、重建指定结果、理解选择和继续工作。目录齐全、文档很长、所有格子有字都不构成完成证据。

每个字段只在需要时填写实际信息；职责可登记为未启用，不创建空的结果、决定或审计文件来凑结构。已有信息用精确引用，不在 PROJECT、PLAN、TASK、findings 重复抄写。例行小动作记在 TASK；只在范围、取舍或解释发生重要变化时新增决定。发现规则反复增加填写成本却不能解决真实问题时，在现有审计记录中提出合并或裁剪理由。

## 2. 分阶段投入，允许往返

采用 Stoudt 等正式论文的 Explore／Refine／Produce 作为工作重点，不新增任务状态枚举；它与探索／确认的科学证据性质分别记录。

| 阶段 | 当前受众与最低要求 | 暂不要求 | 何时加强 |
|---|---|---|---|
| Explore：探索 | 研究者；保留问题、输入、尝试、失败、代码／配置身份与下一步 | 不为每个临时尝试制作可公开交付包 | 有候选解释、开始跨任务复用或他人接手 |
| Refine：收敛 | 合作者；固定比较条件、复用接口、关键测试、环境与代表性复跑 | 不把所有探索路径都包装成通用软件 | 需要固定采用或外部复用 |
| Produce：形成成果 | 明确目标受众；完成采用映射、接手复跑、访问与许可、说明与维护边界 | 不自动公开受限数据，也不自动承诺长期维护 | 按具体交付标准验收 |

可以从任意阶段退回探索，并记录理由与受影响采用范围。预先固定输入和执行身份、原始数据只读、隐私及终评准入在所有阶段保持，不因轻量探索放宽。

## 3. 分开声明四种证据

按 The Turing Way 的语境描述，不声称所有学科术语一致：

- 同数据、同分析的计算复现：明确软件／硬件、随机性与预期结果；用事先说明的容差判断。
- 同数据、合理替代分析的稳健性：说明改变的分析选择及结论是否保持。
- 新数据上的复核：明确新样本／队列和保持的方法条件。
- 推广范围：依据实际人群、环境和方法变化的证据限定；不能只靠一次复跑宣称可推广。

这四项分别记录已检查、失败、未检查或不适用及理由。计算能重跑不证明研究设计正确。对本项目没有执行的稳健性或外部复核，不要求伪造完成状态；是否需要由研究问题与采用标准决定。

## 4. 以接手者为验收对象

在 PROJECT 说明目标受众、协作者角色、求助入口、贡献与审阅方式，以及如何认可实际贡献。个人项目可简写为本人、未来接手者及现有联系渠道，不制造虚构团队。使用清楚文字、数据字典、图表说明和可复制命令，尽量降低领域或环境经验门槛。

阶段交付时用 [接手复跑模板](../assets/templates/reproduction-check.md) 做一次界定范围的检查：从说明定位材料，按文档准备环境，重建指定产物，对照预期结果，记录偏差和解决办法。作者自检与独立接手检查分开标记；没有真正的独立执行者不能声称独立验证。

## 5. 尽可能开放，必要时受限

数据、代码和文档分别记录访问方式、许可／使用条件、联系人和限制理由。不把 FAIR 或可复现理解为必须公开下载。受限材料保留可定位身份、获批访问流程、可公开元数据边界；可提供合成或脱敏样例验证接口，但样例不能替代对真实结论的复核。

不擅自选择开源许可、扩大共享或上传数据。现有授权内整理可发布材料，未授权部分保留清楚的访问说明。数据涉及的人群、预期用途、可能误用和局限在 PROJECT／findings 明确；需要专门伦理审查的事项记录现有依据，不由模板替代审查。

## 6. 环境、手工步骤和退出能力

记录实际环境创建／恢复方法、直接依赖及适当的锁定信息；涉及硬件、外部服务或非确定性时保存条件及容差。工具版本列表不是恢复成功的证明，尽可能用独立环境做代表性复跑；未做写未验证。

不能自动化的清理或交互步骤保留原输入、输出、操作规则、操作者与时间，以及可重做的说明。Snakemake 从已明确的输入继续，不假装缺失的手工步骤已经自动化。

交付说明最后验证日期、维护责任、已知限制和材料保存／取回方式；停止维护也应明确。保留标准格式和可读说明，检查脱离当前 AI、任务工具和原始机器后能否定位与复用材料。不要求为一次性探索构建永久服务。
