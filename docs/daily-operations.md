# 科研日常操作规范

本页是立即可用的操作入口；开源架构、宿主适配和未来工程不作为开展研究的前置条件。已有项目保留目录与入口，通过引用接入。以下为示例医院科研场景的明确约定；迁移到其他机构时核对其授权与数据政策。

具体项目的 plan、LOG、进度、结果模板、判断与采用统一按 [结构与记录规范](../structures/documents/GUIDE.md) 管理；开工查审计到期日，收尾核对记录一致性。

## 项目全貌先定位

项目结构、大小项目关系及共享依赖按 [项目架构规范](../structures/project/scope.md)。接手先定位项目群／项目／主线，复用项目地图；不同主线独立状态和台账，父级只汇总。小项目不强加层级，老项目先映射再讨论迁移。

## 第 0 步：没有新工具也能开始

用已有项目当前页和 LOG 记录问题、证据、判断及下一步。没有 Snakemake、RO-Crate 或公共程序时手工维护相同语义；不为补平台暂停已授权研究。能力不足只限制对应执行或合规声明。

默认最小判断条如下，可放在现有问题模板里，不要求另建文件：

```text
问题：本次要回答什么，适用人群／数据／方法范围是什么？
结果：观察到什么，引用具体 run、组合及产物；未检查写明。
结论：证据支持到哪里，哪些解释仍待核对？
影响：继续、调整、暂缓或停止哪一明确范围？
下一步：做什么、为什么、完成标准是什么？
重试条件：什么新数据、方法修正或证据出现才值得重试？
```

复杂分析可扩展为表格；六项信息已在现有模板中时直接引用，不重复抄写。AI 起草与研究者确认分开记录，沿用已有授权，不逐次机械请求批准。

## 开工与收尾

开工先读项目入口、当前页和已有改动。在写入前按项目 VCS 约定保存可恢复快照，不混入其他人的未完成工作，不隐含 push 授权。只读检查无需制造提交。

开局三件事：读当前页；核对新增结果、回执、待解释和行动状态；确定本轮最值得做的一件事及理由。远端未知就写核对时间与边界，不能把旧回执当当前状态。

收尾四问：待解释清了吗？判断落了吗？行动清单对了吗？首屏对吗？未清的保留数量、原因和接续位置，不为“全过”伪造判读。代码同步与研究收尾分别报告。

首屏八字段：研究问题、当前阶段、已有认识、在跑、卡点、待解释积压、下一步、核对边界。在跑包含机器、作业号、墙钟余量与核对时间；未知值明确写未知。待解释超过项目阈值时优先判读，未设置阈值则提出建议，不擅自编数。

## 数据安全：四个出口逐次检查

- 发布口：检查包、图表、日志、文件名和元数据中的直接标识及可识别信息；核对许可和授权后才发布。
- 超算口：只传所需脱敏材料；姓名映射 naming/ 永不上超算，打包清单显式排除。
- 仓口：naming/ 永不入仓；台账、LOG、判断条及路径中不落姓名或含身份的原始文件名。论文小件入仓前同样检查。
- AI 口：读取或发送给 AI 的内容先脱敏；不把姓名映射、原始身份文件或含身份的日志直接放进提示词、工具输出或上传包。优先本地脚本生成脱敏摘要，再交给模型。

姓名与被试 ID 的映射只保存在受控数据盘 naming/；被试主键 ID 一经发出永不重用，排除或撤回只改变状态。已有 ID 不批量改名。具体格式遵循项目约定，不把某项目的编号前缀推广到所有项目。

## 原始材料与备份

raw 只读。重要材料保留两个独立、可核验的副本；同盘两个目录不算第二介质。原始数据应有第二介质副本；发现唯一副本先登记风险和补备份安排，不对其执行不可逆处理。

论文级 run 的脱敏小件（来源清单、配置、表图等）随私有／获授权代码仓版本保存，同时保留数据盘副本；体积和仓库政策不允许时保存可取回引用及独立备份，不强塞大文件。敏感内容不得为满足备份规则而入仓。

阶段冻结或论文采用前核对第二副本；备份记录至少含源和目标、材料身份、时间、文件数量／大小、内容校验结果和恢复抽查范围。复制命令成功不等于备份验收。代码推送不等于原始数据已备份；备份、回传、验收分别记录。

## 留出集与终评准入

留出集终评是独立受控步骤，不加入 Snakemake 默认目标、普通参数扫描或自动重试。运行前必须核对项目中已经记录的准入条件和确认依据，包括候选方案冻结、开发阶段检查完成、终评用途与使用历史。

缺失条件或授权时只暂停终评，其他已授权工作可继续。已明确授权无需重复询问，但必须能定位依据。demo-project 的历史样本量不作为其他项目固定样本数。终评结果参与后续选型时明确改变其证据性质，不继续声称未触碰验证。

## 判读、报告与采用

不同人群、目标、划分和用途分组比较。QC 改变人群、融合取交集时，不能直接把分数差归因于方法。停止决定必须限定数据、人群、特征、方法与评估范围。

报告四条：交代实际测过的全部相关变量；交代全部相关条件与尝试（含失败和负结果）；剔除规则与剔除前后结果双报；协变量调整与未调整结果双报。确实不适用或无法计算时说明原因，不编造补充结果；明细可放补充表。

论文级关键数字设置独立复算员：用干净会话或独立检查者，从原始结果和明确计算规则复算，不只复述已有结论。LLM 可以组织检查，数值交给可执行程序；记录输入、命令、误差和差异处置，不把同一模型的再次赞同当独立证据。

采用前三项就绪检查：代码可追溯；验证方案完整；无未解决、影响该结论的疑点挂账。未通过的结果保留为探索材料，不能标为已就绪。通过后记录论文图表→具体结果行→run→配置／代码／输入的采用映射。

在接手、依赖变化和采用前扫描产物是否过期：输入、代码、有效配置、环境或上游产物是否变化；记录是“需要核查”还是“已确认失效”。保留旧产物，按影响范围重算，不自动删除，也不凭 mtime 判定科学失效。

## 文档并发

同一时间只由一个工具写同一份规范或问题页；先明确本轮写入者，写前重读，落盘前比较基线。发现他人更新先合并，不能用旧稿覆盖。文件锁仅辅助本机协调，不证明跨机独占。

## 与设计书的关系

本页规定日常行为；[设计书](design-plan.md)描述未来实现。公共程序当前只完成记录校验、去重、视图回填和基础研究包导出，不自动强制执行所有安全、备份、终评和采用检查。运行与交付前由 skill 按本页核对，不宣称脚本通过即全部合规。

## 随机性与候选稳定性

涉及随机训练、初始化或随机划分的正式候选／论文比较，预先确定适当的多 seed 或重复划分设计，报告分布、差异与排序稳定性；区分训练随机性和样本划分随机性，按影响结论的来源设计重复。单次随机运行只作探索，不据此宣布稳定最强或正式采用。次数与预算按研究问题确定，不虚构通用次数。确定性分析说明不适用；独立外部验证、终评次数和授权仍按原设计执行，禁止为凑重复反复使用留出集。
