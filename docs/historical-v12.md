## 一、这套规范统一什么，不统一什么

日常管理首先保证四件事：代码改动有版本，公共模块只维护一份，项目有明确目标与下一步，跨机器和跨会话能接着工作。RO-Crate 统一描述运行和交付所需材料，连接代码、配置、输入、产物与说明。

根本目的不变：任何时刻，一个人或一个全新 AI 会话，只看仓里的记录，就能答出四问。这个项目想回答什么研究问题。已经知道了什么，含最强结果和已排除的死路。还不知道什么。下一步打什么。并且论文里任何一个结论，都能顺着记录追回当时的输入、代码、参数、数据和机器。

这一版在前半句之外加了后半句：接入新项目时，不许再为它写一套出生证、台账、回传、汇总和接力程序。科学方法可以不同，管理与计算的公共机制只维护一份。

统一的是六样东西：什么是输入，什么是一次执行，什么是结果，什么证据可以支持判断，怎样登记改变，怎样交接。不统一的是：算法、研究问题、科学取舍。示例医院分类、示例研究A 方差分析、Meta 文献提取遵守同一条骨架：

> 固定输入和方法 → 执行 → 验收产物 → 形成有来源的判断 → 决定后续行动。

它们的验收各不相同：分类查被试划分和折内处理，方差分析查设计和重复测量，提取查原文身份和订正。框架统一验收结果的表达、引用和状态，不假装这些检查共用同一段科学代码。

需要新能力时，先查公共件，缺口补进公共件。这条边界直接回答“以后会不会又乱”：差异集中在研究内容里，公共机制只有一套维护源。

四层结构不变，每层统一的是机制，不只是文件形态：

| 层次 | 全项目共用 | 对应 |
|---|---|---|
| 原则层 | 研究循环与计算流水线分工、三分状态、唯一住址、维护成本观 | 第二节 |
| 记录层 | 七类对象、来源标准、统一接口、判断格式、当前页 | 第三、四节 |
| 时机层 | 计划、执行、验收、判断、改变安排、交接各时刻 | 第五节 |
| 工具层 | jj/Git、RO-Crate 工具、公共件、Snakemake、Aim、MATLAB 适配、多机多 AI | 第六节 |

## 二、原则层：八条

每条写清保护什么，没有它会翻什么车。

**原则一，研究循环和计算流水线分开。**研究循环包括提问、探索、解释、比较、改方向，可以回头。计算流水线包括转换、预处理、建模、统计、出图，在一次固定尝试里应可执行、可检查（stoudt 2020 的区分）。调度器安排算什么、哪些产物要重做；研究判断决定值不值得继续、能不能进终评。不能让调度器管理科学结论。没有它，引擎会把你锁死在某条流水线上，或者反过来，流水线天天重算没人管。

**原则二，一次尝试要有一个交代。**尝试从“为什么值得做”开始，到“得到了什么、怎么判断、接下来怎么办”结束。同一配置的六次冒烟是六条执行记录，合起来只算一个工程问题。保护研究记忆。没有它，示例数据集那批同配置时间戳变体会被数成许多个实验。

**原则三，执行成功、证据可信、研究采用三分开。**程序跑完是执行事实。输出通过指定检查是证据可信。被论文或报告引用是研究采用。三者不自动传导：跑完不等于知道，置换检验显著不等于可以进论文，AUC 更高不等于更强证据（nback 约 0.65 的 CV 外预筛就是例子）。执行失败也绝不登记为科学负结果，回归批次撞六小时墙全损，如果当时顺手写成“回归方法无效”，就是一次冤案。

**原则四，事实、判断、安排各有唯一住址，公共机制只有一份维护源。**事实住出生证和台账，判断住 LOG，安排住当前页的行动清单，规则住 AGENTS.md。一处写真，处处引用。公共件（出生证、台账、回传、汇总、状态）只有一份，项目引用固定版本，不复制不改分叉。保护单一真相。demo-project 台账多份且表头互不一致、示例医院台账多种载体互不连通，就是反面教材：同一个事实有多个互不一致的权威。

**原则五，每个结论带适用范围。**正结果、弱结果、负结果都写明针对哪个任务、哪个目标、哪批数据、什么评估条件。任务E 当前路线停止，不能扩展成 任务E 永远无用。EEGNet 已试设置无信号，不能排除没做过的 任务A。报告纪律四条跟着走：列出全部收集变量，报告全部实验条件，剔除后同时报未剔除的结果，协变量分析同时报无协变量结果（simmons 2011）。上百次尝试的整体属于非确认性研究，p 值不当确认性结论用。

**原则六，判断可以改，历史不删。**补数据、修代码、改标签后允许重新评价。新判断引用旧判断，写明条件变了什么。旧结果、旧决定原样保留。保护论文追溯：修完重复折 bug 后如果只剩最新结论，就无法解释旧稿为什么用了另一组数。

**原则七，当前状态带核对时间。**当前页顶部必须写事实核对到何时、哪些机器未核对。判断区分已确认和 AI 建议待确认。断网、会话死亡时显示信息缺口，恢复后合并。作业没有新消息，不等于还在跑，也不等于失败。作业A 只能写“最近记录在跑，实时状态未核对”。

**原则八，轻量按总维护成本衡量，投入按风险分级。**一个成熟工具可能比十份几十行的自写脚本更轻（clary 2022 的 Economy 原则）；反过来，一个能启动的开源服务也可能因升级、故障、备份吃掉更多时间。选型看四件事：替代了多少重复劳动，失败后能否恢复，数据能否完整带走，你要维护多少自定义代码。项目投入同理：风险等于复杂度乘影响（Turing Way 矩阵），低风险脚本 dry run 过就行，进论文的分析才配全套记录；同时活跃的项目设上限，超了先收一个再开新的。

## 三、记录层（上）：对象、标准、接口

### 1. 七类对象，所有项目说同一种话

| 对象 | 白话含义 | 示例医院例子 | 其他项目例子 |
|---|---|---|---|
| 问题与计划 | 准备回答什么，怎样比较，什么条件下收敛 | 任务B 融合能否增加预测信息 | 哪条预处理管线更稳定 |
| 输入与数据产品 | 这次实际使用的确定材料 | 某份宽表、标签、纳入名单、划分 | 某批预处理结果、量表订正表 |
| 方法与环境 | 实际算法、代码、参数、运行条件 | stability 加 PCA 加 LDA 及环境 | MATLAB workflow、R 模型、LLM 提示词 |
| 执行 | 某时某地实际做的一次计算或人工操作 | 某个 run 与 Slurm 作业 | 一次人工仲裁、一批报告渲染 |
| 观察与产物 | 计算得到的数字、表、图、模型、检查结果 | AUC、置换分布、报告 | 效应量、QC 表、提取响应 |
| 判断与决定 | 观察支持什么、限制是什么、接下来怎么办 | 当前候选；停 任务E 当前路线 | 某特征不稳；提取错误需改规则 |
| 采用与交付 | 哪些结果被哪项交付使用 | 论文结论及图表 | 医院报告批次、标书主张 |

固定关系：输入被执行使用，方法指导执行，执行产生产物，产物支持或反对判断，决定建立或改变行动，交付引用采用的判断与产物。一次尝试围绕一个问题，可关联多个执行。继续使用已有 run_id 和资产引用，不另造编号体系。

### 2. 研究包采用 RO-Crate

先把两个容易混淆的名字定位说死。The Turing Way 是一本给人读的开源手册，讲怎么做可重复研究：版本控制、环境、数据管理、测试、文档。它不是软件，不安装，也没有数据格式，用法是把做法抄进来。本规范的原则已经抄过它，它退回参考书位置，平时不再出现。RO-Crate 是一个打包规格，用一个元数据文件描述一包研究材料和它们的关系，让别的软件和人读得懂。它不是日常管理方式，只在交付和归档那一刻由公共件生成快照时用到。一句话：一个教你做法，一个规定包装，不在同一层，不存在二选一。

RO-Crate 用标准化元数据描述一组研究材料。官方教程从已有文件夹开始，逐步补充包的说明、文件与关联信息，适合在现有项目上增量接入。[教程入口](https://www.researchobject.org/ro-crate/tutorials)、[文件夹入门](https://www.researchobject.org/packaging_data_with_ro-crate/02-folder-as-crate-root.html)。

本方案用它描述项目阶段快照和正式运行包：这是什么项目或运行，使用哪份代码与配置，输入在哪里，产出了哪些文件，以及相关说明和责任人。代码历史由 jj/Git 保存；目标、行动和决定由项目记录保存；RO-Crate 将相关材料连接起来，供交接、检查和归档使用。

日常开发沿用现有目录。正式比较形成最小研究包；采用、交付或阶段冻结时固定快照。公共件从已有运行记录、引擎回执和产物索引生成元数据，避免手工重复登记。敏感原件留在受控区，通过明确引用和访问条件关联。

先采用基础 RO-Crate。确需描述脚本执行时再选 Process Run Crate；确需工作流运行记录时再选 Workflow Run Crate。profile 的增加必须对应具体读取或交付需求。[运行 profile 集合](https://www.researchobject.org/workflow-run-crate/profiles/)。

生成器、标准版本和校验器版本须固定并验证兼容性。JSON 能解析、元数据符合标准、文件完整可取回、分析可以重现，是四项不同检查。未通过相应校验时，只称内部记录，不声称符合某个 profile。

### 3. 统一接口：每个计算步骤只提供四件事

| 接口内容 | 要求 |
|---|---|
| 输入声明 | 指向确定数据产品及方法、配置，解析后用绝对路径 |
| 调用入口 | 能独立运行的命令或函数，成功失败可识别 |
| 输出声明 | 预期表、图、模型或数据产品，加最低验收条件 |
| 观察摘要 | 结果对象、指标或效应、比较上下文、对应原件 |

Python、R、MATLAB 同一接口，实现入口可以不同。科学代码只管科学计算；来源、状态、交接、摘要校验由公共执行包装负责。

观察摘要的字段固定：question、task、target、dataset_id、input_type（特征表还是波形，专治 waveform 式挂名）、metrics、baseline、tests（检验和 p 值）、seeds、比较上下文（ML 里是划分、目标、QC、人群；统计里是设计、模型、校正；QC 里是批次、阈值）。没有 p 值的预处理不编 p 值。ANOVA 表、模型系数、每折预测等丰富产物按原格式保存，共同摘要只是可检索目录。运行记录字段固定：run 身份、所属问题、代码内容与入口、有效配置、输入引用、环境与机器（含节点和 GPU 型号，isdahl 的提醒）、起止与执行状态、输出引用。

### 4. 数据产品与研究运行分开复用

预处理产物是一份数据产品，可被多个分析使用。改分类器，新建分析运行并引用原数据产品，不重算 MATLAB 预处理。改预处理参数，产生新数据产品并保留来源，之后的模型引用新产品。这界定引擎的复用范围：数据生产工作流与分析工作流分开，通过确定产物连接，不能把所有计算塞进每次新建的空 run 根目录再指望引擎跨目录识别复用。

## 四、记录层（下）：判断、状态、当前页

### 1. 判断条六行，判断的唯一住所在 LOG

统一判断保存：问题、证据、解释、适用范围、决定、后续行动。落成固定六行格式，字段名照抄：

```
## 2026-08-01 任务E 线停止
- 问题：任务E 特征能不能预测 任务C（configs/<task>_line1.toml）
- 结果：AUC 约 0.52，临床基线约 0.60（run 0002_demo）
- 结论：停止这条路线（已确认）
- 影响：撤掉同条件的参数扫描，结果保留
- 下一步：无
- 重试条件：新数据或换特征时再提，须说明和这次有什么不同
```

六行各答一问：当初想回答什么，数字是什么，数字支持什么，这个结论改变了什么安排，紧接着做什么，什么情况下值得再试。

三条硬规矩。结论一词从五个里选：支持、不支持、存疑、无效、被取代，汇总和排序靠它（ChatGPT 的建议）。判断只认落笔的：Milner 的规矩，书面确认才算数，AI 会话里说得再圆满，没进 LOG 等于没发生。下一步多数写无；写了具体的事，就同时抄进行动清单，行动清单一半从这里长出来（智谱清言的建议）。

重试闸门：重新提议一条已停止的路线，必须写明和上次有什么不同。没写差异的提议直接打回。

### 2. 状态三栏，各写各的

| 状态栏 | 谁写 | 取值 |
|---|---|---|
| 执行状态 | runner 或调度器 | queued、running、succeeded、failed、interrupted |
| 证据状态 | 验收检查 | 未验收、通过、部分通过、不通过；来源缺口单记（如 no_git） |
| 判读状态 | 汇总步骤回填 | 待解释、已判读、待复核 |

三栏互不冒充：调度器只写事实，领域检查只写检查结果，确认记录只写科学处置。当前页汇总三栏，不按最新文件或最高分覆盖。

### 3. 当前页：首屏、矩阵、行动清单

当前页（PLAN.md）分人写区和派生区。人写区四样：研究问题（每条主线一行加预期交付）、阶段目标（按待回答的决定表述）、留出集和终评的准入条件、排序原则的本地修正。派生区三块，由公共渲染器生成，人写区不碰。

首屏八个字段，一屏以内：

| 字段 | 内容 | 来源 |
|---|---|---|
| 研究问题 | 每条主线一行 | 人写区引用 |
| 当前阶段 | 本阶段要解决什么决定 | 已确认的判断 |
| 已有认识 | 最强候选、弱证据、已关路线各一行 | LOG 最新确认 |
| 在跑 | 作业号、机器、墙钟余量、核对时间 | 台账加回执 |
| 卡点 | 数据、方法、工程、外部 | 疑点登记加受阻行动 |
| 待解释积压 | 待解释结果条数，超过阈值先判读，再开新的计算 | 判读状态计数 |
| 下一步 | 当前最值得做的一件，带一句理由 | 行动清单排最前的一件 |
| 核对边界 | 更新时间，未核对的机器 | 汇总时自动盖 |

矩阵一张表，按任务、目标、数据产品、评估条件分区，不同队列不同口径不混榜。列：路线或方案、数字（指标加基线加检验）、判断（引 LOG 日期）、适用范围和限制、run 来源。一行可关联多个 run；真正换了任务、目标、数据或评估才分行。探索行全保留，测过多少关系要可数（ioannidis）。同一 run 内多方案各归其位：示例医院 run_0001_fusion 里有拼接、后期融合、临床联合三种结果，摘要引用具体 section，增量约 0.10 是联合模型相对临床基线约 0.50 的提升，脑模型自己是约 0.70，生成器写清关系后不会把约 0.10 挂错对象。负结果四项说明：试了什么，在哪些条件下没达到什么标准，因此停到哪一步，什么新条件出现才值得再试。

行动清单一张表，每行一件事，事写成问题：比如“行为特征能不能补强融合候选”，不写“跑 behavior 脚本”。列：做什么、来源、状态、前置条件、完成标准、排序理由。八种状态：未开始、已承诺、在跑、待判断、受阻、待复核、暂缓、关闭。排序四规则：先做影响现有结论可信度的核查。再做有根据且结果能改变下一步决定的尝试。信息价值相近时选成本低、前置齐的。留出集终评单独设准入条件，不因为排在列表里就开跑。

### 4. 脱敏四口，论文采用过就绪检查

脱敏从两口扩为四口：发布口、超算口之外，加仓口和 AI 口。仓口：台账、LOG、判断条不落姓名和原始文件名。AI 口：贴给任何 AI 的内容先脱敏（Poe 点出两口管不住 AI 会话这个真实风险）。

论文或报告采用一个结果前，过三项就绪检查：代码可追溯、验证方案完整、无疑点挂账。通过后写进采用映射（paper.yaml 记每张图来自哪些 run 和判断），打 tag 冻结。

## 五、什么时候做什么（将来做成一个 AI 技能）

这一节按 AI 技能的方式写：每个时机给触发条件、动作步骤、出口条件。将来整理成技能文件时整节搬过去，不再改结构。触发条件写在每段开头。

**开工：AI 进入项目要干活时。**步骤：一，jj 存档，坏改动随时能回退。二，读当前页首屏，知道现在在哪。三，核对增量：台账新行、远端回执、待解释、行动清单状态变化。四，读行动清单排最前的一件，向你说出下一步建议和理由。出口：能回答“现在在哪、接着干什么”。

**提想法：你或 AI 提出一个新尝试时。**步骤：一，查既有结果和负结果，过重试闸门，已停止的路线必须写明和上次有什么不同。二，起草配置五段和行动清单条目。三，你补研究取舍，认可入列。出口：配置和清单条目落盘，状态未开始或已承诺。

**提交计算：实验定稿要跑时。**步骤：锁输入、代码、配置，起 run_id，写初始来源，交给机器。出口：run 建立，执行状态 queued 或 running。

**结果回来：回执到达或发现 run 结束时。**步骤：一，落出生证、观察摘要，台账加行，判读状态待解释。二，验收检查，写证据状态。三，当前会话不在场就留给下一会话。出口：三栏状态齐，待解释可见。

**判读：有待解释结果且你在场时。**步骤：一，AI 对照基线和预写条款，起草判断条六行。二，你一句话确认。三，AI 落笔三处：LOG 追加，台账判读翻已判读，当前页更新（矩阵行、行动清单、首屏）。出口：待解释数减一，判断可追溯。

**发现 bug 或数据疑点：任何时候。**步骤：标受影响结果为待复核，登记核查事项进行动清单，暂停相关自动推论，你定处置口径。出口：疑点有登记，影响范围有标记。

**收尾：你说今天到这，或会话要结束时。**四问：待解释清了吗。判断落了吗。行动清单对了吗。首屏对吗。问完写一行接续位置进 LOG 末尾。push 照做，但 push 证明代码同步，不证明研究收尾。这四问写进 AGENTS.md 开头十行。出口：四问全过，接续位置落盘。

**中断恢复：新会话发现上一会话没走完收尾时。**从待解释和已起草未确认的判断接手，重新起草，等你确认。事实没丢，不用回忆，不用重跑。

## 六、工具层：代码与项目管理为主，公共件只维护一份

先给一张“遇到什么、用什么”的表。日常要记的只有一件事：所有项目天天用的，是 jj 加公共件。其余都是特定场景才出现的工具，按表查。

| 你遇到什么 | 用什么 | 说明 |
|---|---|---|
| 所有项目的每一天 | jj/git 管版本，公共件管出生证、台账、回传、当前页 | 唯一的日常答案 |
| 一条链多阶段、常改其中一段、改完全链重跑（示例研究A、多中心研究） | Snakemake 编排 | 科学代码不动，只在外面包一层 |
| 要横向比较几十个 run 的指标 | Aim，只在本机导入 | CSV 里的终值不够看时 |
| LLM 批量提取、核验、比提示词（Meta） | Opik 试点 | 只在这一类工作线 |
| 单步分析、综述、申报材料 | 什么都不装 | 只写配置、判断、当前页 |
| 论文定稿、交付归档那一刻 | RO-Crate 研究包快照 | 公共件生成，不用手写 |

拿不准时按保守侧选：先用已有的 jj、公共件、手工表，真觉得痛了再上表里的工具。细节看下面各节。

### 1. 公共件四部分，只维护一份

| 公共部分 | 包含什么 | 各项目怎么用 |
|---|---|---|
| 工作流模块 | 通用启动、验收、汇总、报告，可复用数据处理模块 | 选固定版本传配置 |
| 运行适配 | Python、R、MATLAB 命令包装，旧出生证读取，摘要规范化 | 现有算法接一次 |
| 来源与交换 | 记录、引用校验、研究包生成、回传导入去重 | 不再各写 manifest、registry、fetch |
| 研究阅读视图 | 当前页、矩阵、行动清单、论文映射渲染 | 同一渲染器按归属过滤 |

基础件有版本号和最小测试，项目固定所用版本。现有项目先写读取适配，不改写历史出生证。公共件边界克制：不自写排队算法、调度器、实验数据库、网页看板、LLM 评估平台，只补科研语义和工具接口。

### 2. Snakemake：多阶段计算的默认编排器

接管：输入到输出的依赖，哪些目标要重做，CPU 内存环境执行位置，失败重试和运行统计，结果表图报告连成目标。不接管：数据有没有入组循环性，哪条路线值得继续，留出集能不能开。

避免每项目一个巨型 Snakefile：重复规则做公共 module，项目只组合模块加科学配置。研究参数与机器资源分开，现有 TOML 不必改格式，公共层读取，禁止两份含义相同的手写配置。本机和两台超算的 executor 配置在公共层有唯一维护位置。

增量执行不破坏历史保存：正式封存后不覆盖，参数或方法变化形成新分析记录。默认不用 temp 自动删中间产物，不自动清理失败证据。引擎内部 metadata 帮计算，研究包管长期解释，不把会被清理的 .snakemake 状态当论文证据。

MATLAB 三个坑提前写进适配层：MATLAB 不认引擎的 threads 指令，规则写 threads 1 或代码里 maxNumCompThreads。并行规则会撞 MATLAB license 数量。必须 matlab -batch，-r 不回传退出码。

试点：示例研究A 的一条 MATLAB 到特征表到 R 统计到报告链先走，验证跨语言和数据产品复用。示例医院先让引擎整段调用已验证的分类回归运行器，不把每折每次置换拆成规则；要解六小时墙，再按算法现有可保存单元拆分并验证等价。

### 3. Aim：ML 和统计比较的本地浏览层

计算机产生共同摘要，本机统一导入 Aim。Windows 和超算不装，不要求超算连本机服务。Aim 是可重建的比较索引：确切输入、结果原件、判断留在研究包，关掉 Aim 计算和交接照常。

防止比较错对象：导入器必须带项目、问题、任务目标、输入产品、人群、验证方法、结果行、基线，任务C、任务B、回归分别过滤。重复导入依研究结果引用找到已有 Aim 条目再更新，不自造 hash。

采用门槛四条：来源能定位，重复导入不新增，错误高分可隔离（约 0.65 那种 CV 外预筛要能单独归探索），关闭数据库不丢证据。退出条件：若仍需逐条进 Aim 补数据，或安装兼容、数据库恢复、界面操作长期占时，保留共同记录并退出，不因此推翻框架。

### 4. 代码、项目记录和研究包各负其责

代码版本沿用 jj/Git。项目内保留一份活代码；普通修正就地修改，历史由版本库保存。不同科学方法用明确命名的模块或配置并存。公共工具只维护一份源码，发布版本供各项目固定使用；升级须通过代表性检查。

正式运行须能恢复实际执行的代码。提交号不能覆盖未提交修改：公共入口检查工作区，保存必要差异与未跟踪执行文件，或保存完整代码快照，并记录校验信息。缺少执行代码时不得标记来源完整。

项目入口说明当前工作线、运行方法和关键记录位置；当前页管理目标、阻塞和下一步；LOG 保存改变及理由。完成任务时引用代码变更、运行结果或交付物，并记录验收。RO-Crate 描述这些材料之间的联系，便于交接和归档。

RO-Crate 接入复用现成工具：

| 工具 | 用途 | 接入方式 |
|---|---|---|
| ro-crate-py（Python 包名 rocrate） | 读写研究包元数据 | 公共导出器调用，各项目共用适配 |
| CRS4 rocrate-validator（Python 包名 roc-validator） | 检查选定标准与 profile 要求 | 导出验收时运行，保存校验结果 |
| ro-crate-html | 生成 HTML 预览 | 按需生成，供交接阅读 |
| Crate-O / RO-Crate Playground | 学习和检查示例 | 辅助使用 |

本轮已阅读[官方教程与工具目录](https://www.researchobject.org/ro-crate/tools)、[ro-crate-py README](https://github.com/ResearchObject/ro-crate-py) 的创建、读取、引用和版本选择说明，以及 [CRS4 校验器 README](https://github.com/crs4/rocrate-validator) 的校验范围与命令行说明。预览和图形编辑器仅核对目录介绍，尚未安装或实测。工具应在独立 conda 环境验证后，再固定版本接入。

### 5. MATLAB 薄适配

example_pipeline 的数据容器、算子、ExampleEngine 继续承担科学计算。外面加一个可独立调用的入口：接受确定输入、有效配置、输出位置，调用真实工具版本，返回产物清单、失败范围、质量摘要。同一个包装用于 示例研究A、示例队列B、示例医院、多中心研究。Windows 走 WSL 装引擎不可靠时，先在 Windows 直接跑同一 batch 包装再回传，仍符合框架。

### 6. 体检六件，挂在公共件里

文档里写的路径存在（示例项目台账指向空文件的教训）；台账和 manifest 对得上；判读滞留报警（待解释超三天列出）；raw 目录只读；论文级 run 小件在 git 里；产物过期扫描（manifest 登记输入哈希，扫出“输入已变产物没重跑”清单，calkit 的思想）。

### 7. 其他工具取舍

| 候选 | 决定 | 理由 |
|---|---|---|
| Snakemake | 默认编排器，先试点 | 模块复用减重复；集群边界实测 |
| Aim | 首选本地浏览，试点 | 替代手工比较；证据可重建 |
| RO-Crate + ro-crate-py + CRS4 校验器 | 采用研究包标准，工具接入待验证 | 复用元数据生成与校验，减少逐项目自定义格式 |
| Nextflow | 同层替代，不并行推第二套引擎 | 已有社区流程可沿用时再议 |
| ClearML、W&B | 本阶段不用 | 云撞合规，自托管养服务 |
| Calkit | 借研究包思想，不装 | 地基是已否决的 DVC |
| Taskwarrior | 不用 | 行动清单在当前页，AI 读纯文本更易 |
| 目录模板包、R 教程 | 查阅素材 | 不复制成新规范 |

旧否决继续有效：DVC、MLflow、git-annex、台账换数据库、三层 ID 体系。选型前提这一轮已变：你明确允许考虑合适工具，所以 Snakemake 和 Aim 从旧稿的否决与观察位升为试点推荐，判据和退出条件都在上文。

### 8. 多机多 AI

计算分散，证据就地产生：每台机器执行的是已固定的方法和配置，当地先留运行记录和产物，小记录优先回传，大件走既有 rsync 过夜链。不在多台机器上同步正在写入的 .aim 库或版本库目录。同一数据产品在不同机器路径不同，资产身份和校验不随路径变。

访问约束和计算约束分开：密钥六小时过期影响查询传输，作业六小时墙影响计算。控制进程中断后，先用当地回执和调度记录核对仍在跑的任务再恢复，直接重启引擎可能重复提交。

多 AI 共用入口和记录协议：接手读当前页，核对新回执、待判断、行动，再按证据进源文件。提新尝试先查既有范围和负结果。正式判断、总排序、项目汇总由一个写入者短时合并，不让最后保存的人覆盖前人。不要求各 AI 内部记忆统一，要求任何被采用的事实、判断、承诺都进共同记录。

## 七、示例医院标本走一遍

仓库实况：主仓 <legacy-project-root>，results 在 .bak<日期> 备份里，台账多种载体互不连通，无 LOG.md。数字以现场核对为准。

**第一幕，接入不改写历史。**多任务宽表、波形、标签、划分登记为输入数据产品。备份里有若干 run：有 manifest 的由公共适配读取进新台账，没有的登账标“证据不全”。experiment_manifest 示例.csv 空壳归档，run 内 leaderboard 和超算 leaderboard 的数字经核对汇入矩阵，旧文件不删。项目状态文件各节里的判断逐条搬进 LOG，标注“首次整理，来源：交接文档”。手写的全尝试记录若找到同法接入。负结果逐条挂回，挂不上的标“历史记录，证据待补”。

**第二幕，一个 run 的多方案各归其位。**run_0001_fusion 里有拼接、后期融合、临床联合三种结果。共同摘要引用具体 section：脑模型 AUC 约 0.70，临床基线约 0.50，联合模型约 0.60，联合增量约 0.10 是联合相对临床基线的提升。关系写清后，矩阵和 Aim 都不会把约 0.10 挂给脑模型。该记录的 no_git 是来源缺口，查当时打包件能否补齐；出生证存在不代表追溯齐全。

**第三幕，任务E 触发停止条件那一刻。**

1. 执行器完成既定比较，观察摘要落盘：AUC 约 0.52、基线约 0.60、可比条件、检验、run 来源，全部机器提取。台账加行：执行 succeeded，判读待解释。
2. AI 读摘要，对照配置里的 stop 条款，起草判断条六行，写明触发条款原文、适用范围（当前特征集和人群）、重试条件。
3. 你回一句“同意关线”。这是你在整个事件里唯一的手工动作。
4. AI 落笔三处：LOG 追加判断条；台账判读状态翻已判读；当前页更新（矩阵行标“当前路线已关闭”并引 LOG，行动清单撤下同条件扫参并留停止原因，首屏已有认识加半行）。
5. 会话死在第 3 步之前：台账停在待解释，开局三件事把它捞出来，新会话重新起草。事实没丢，判断晚一会儿，不用回忆。

不通过一个 AUC 小于阈值的全局程序永久封死 任务E。不同目标、输入、数据条件出现时，按共同记录写明新条件再提尝试。

**第四幕，约 0.65 不直接变最强证据。**nback 统计预筛在 CV 外。共同摘要保存它的评估上下文，Aim 显示分数，“严格折内候选”的过滤不会把它混入。严格化预筛是新的科学比较，不能靠换显示标签补成折内。

**第五幕，六小时墙。**能独立恢复的组合交给引擎安排重试；不能恢复的算法补保存单元。只做一次通用批处理与恢复约定，下一个 ML 项目不再复制示例医院的 sbatch、补登台账、收尾脚本。回归撞墙那批登记执行失败，行动清单里这件事翻成受阻，另加一条“分批重提”的新事项，矩阵不加负结果行。

**第六幕，作业A 与当前视图。**nback 行为批显示“最近记录在跑，核对时间某时，实时状态未核对”。新会话开局第二件事查它，收到回执转待判断。通道级 FC 已有提取和部分结果，从“还没做”改成执行和待判断；旧总结保留日期，不追认。

**第七幕，数据疑点。**量表分值超上限、健康组分值与分组矛盾、诊断字段存在缺失、入组规则循环性，各登记一条核查事项，排到清单最前面。入组循环性核对具体规则前，不宣布已证实泄漏，也不默默忽略。受影响结果标待复核，退出最强排序。被试剔除规则先写进配置再动手，剔除和保留各跑一份，两份都进矩阵。

**第八幕，收尾。**全尝试记录已经存在，它叫当前页加矩阵加行动清单。验证框架来自人写区，结果、最强候选、负结果、还没做的事来自派生区，产物索引来自台账。写论文时从矩阵挑过就绪检查的行生成 paper.yaml。留出集由阶段准入控制，不因它是个可执行目标就默认允许调度器运行。

## 八、新项目还需要写什么

| 内容 | 新项目提供 | 不应重复开发 |
|---|---|---|
| 研究设计 | 问题、人群、主要比较、判断与停止条件 | 状态和行动清单系统 |
| 数据 | 输入清单、变量含义、主键、纳入规则 | 数据身份、校验、回传框架 |
| 科学分析 | 真正不同的算法或检查，已有方法只填配置 | 启动、收尾、出生证、自动登账 |
| 执行 | 选已有机器与环境配置 | 每项目写 HPC、Windows 调度 |
| 结果 | 给算法接共同输出接口，新类型补一次领域适配 | 新的矩阵和比较界面 |
| 研究解释 | 判断、限制、决定、下一步 | 工具专用接力记忆 |
| 交付 | 指定论文报告采用哪些产物和判断 | 论文来源索引 |

科学差异不保证零代码，但每个同类型新项目的基础设施改动应趋近于零。

## 九、实施顺序

第 0 步，今天：判断层先跑起来。在下一个动手的项目按第五节时机层执行：LOG 六行判断条、判读状态、收尾四问、开局三件事、开工存档。零工具，AI 按格式手工执行。

第一步，固定最小共同约定。用三份真实样本核对对象关系、最小字段、观察上下文、判断格式：示例医院分类结果、示例研究A 预处理与统计结果、Meta 提取与订正。不只拿一个 ML 样本设计接口。

第二步，一条跨语言链加一个浏览试点。隔离 conda 环境 Snakemake 封装 示例研究A 已有链，验证局部变化和失败恢复。独立环境 Aim 导入示例医院既有结果，验证上下文、幂等、退出。不改科学方法，不动留出集。

第三步，抽公共版本，接第二个项目。发布共享模块与适配包固定版本，用 示例队列B 或另一条医院分析链接入，禁止复制修改公共机制。这次接入是抽象够不够的硬测试。

第四步，研究包与工具退出验证。为一个采用的结果生成最小研究包并校验。关闭 Aim 验证结果全景能重建；移开工作流临时状态，验证来源仍可读。

第五步，代码交接与机器实测。去真实 Windows 和超算验证固定代码版本、公共机器配置、路径解析与回执。用一次代码修改、一次运行失败和一次跨会话交接，检查任务状态、代码内容与产物引用能否对应。缺口在公共适配中修复，再推广到其他项目。

第六步，新项目默认模板。模板只装配已验证公共版本、配置样例、操作入口。旧项目按活工作线接入，不以全仓整理为前置。

每步记录接入时间、减少的重复代码、人工补录次数、故障恢复和判断负担。工具增加的维护成本与节省一起算。不先给“几天全部做好”的承诺。

## 十、五个验收测试

**测试一，新会话冷启动十分钟加全链追溯。**换一个没跟过项目的 AI，只给入口，不给聊天记录。十分钟内答四问，拉出在跑、卡点、下一步，每个答案给仓内出处。再加入四个陷阱：CV 外预筛高分、临床联合增量、未核对的旧作业、一个来源缺口，检查它是否正确解释。再指定论文一条采用内容，让它追到判断、结果、输入产品、代码、环境、机器。通过：不把最高分当最强证据，不把缺回执当实时状态，不混淆增量的比较对象，追溯链完整或明确报缺口。

**测试二，判断落账中断。**测试副本模拟三个事件：任务E 触发停止、融合结果回传、回归撞墙。每个事件走到“结果落盘、台账加行”就杀掉会话，不给判断机会。新会话接手，并重复回传一份回执。通过：事实只登一次，三个结果停在待解释区可见，新会话完成 任务E 判断含停止条款引用，撞墙登记执行失败不是科学负结果，从出生证加 LOG 重建矩阵与原矩阵一致。

**测试三，行动对账与防重蹈。**测试副本布置四种状态：作业完成待判断、批次失败待重提、尝试已承诺未提交、一条暂缓。分类回归两个会话分别交回变化，第三个会话汇总。汇总完问两句：要不要再试一次 任务E 特征融合；留出集现在能跑吗。通过：四项各归明确状态，重复回执不重复建任务，任务E 问题先查弃用记录说出重试条件不直接重跑，留出集问题引用准入条件。失败表现：新想法冒充已安排，已停止路线无引用地重提，留出集被顺手提交。

**测试四，第二个项目不写新管理系统。**先接通 示例研究A，再用同一公共版本接 示例队列B 或另一条 MATLAB、R、Python 链。允许填科学参数、加确有差异的算法入口；禁止新增项目专用 manifest、registry、回传、汇总、状态程序。改一个下游统计参数，验证不重做已验收的上游数据生产；改一个预处理参数，验证新数据产品与旧结果分开。通过：基础设施没有第二份分叉，新项目额外工作主要是科学内容。

**测试五，工具和网络故障不带走证据。**隔离副本模拟断网、计算中断、重复回传、同名异内容。关闭 Aim；重新生成浏览索引和项目视图，并独立读取 RO-Crate 元数据和代码快照。通过：原始观察、代码输入身份、判断、行动不丢，重复导入不重登，冲突不覆盖，失败不成负结果，已跑任务不因控制进程重启而盲目重提。系统显示信息缺口，恢复后能对账。
