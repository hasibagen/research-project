# 科研代码维护

## 动作架构与结构依赖

本模块负责实现与配置变更；写入前读取[代码与配置](../../structures/code/GUIDE.md)；实际 IO 涉及 [数据](../../structures/data/GUIDE.md)、[结果](../../structures/results/GUIDE.md) 时一并读取，再读项目对应职责区的实际说明。

流程：任务与代码基线 → 核对模块接口及输出归属 → 实现／验证 → 保存代码身份与影响范围。

输出与边界：代码、配置、验证证据；接口变化同步 code README，新增结构先确认落点。

具体输入、操作、输出和验收样例见 [EXAMPLE](EXAMPLE.md)。目录及接口约束由结构层维护，下文只规定动作。

先读项目入口与已有改动，明确实现范围和验收。沿用项目语言、环境、路径工具与版本控制，不迁移整个项目。方法变体、参数变更、修 bug、输入更新与重复执行分别表达。

修复代码时定位受影响的上游产品和下游结果，追加待复核或失效说明，保留旧产物。配置修改后立即验证解析及实际生效值，包括默认值、命令行和运行模式覆盖。

把科学算法留在项目中；Snakemake 只包装真实输入输出边界。训练范围内的插补、缩放、筛选和调参不得移到全数据共享步骤。验证与变更风险相称，记录实际通过项与未验证范围。版本保存遵守项目 VCS 约定，不隐含推送或发布授权。

写入前按 [日常操作规范](../../docs/daily-operations.md) 保存可恢复快照。仓口排除 naming/、姓名及含身份的原始文件名；给 AI 的内容先生成脱敏摘要。改动后检查依赖产物是否过期，区分待复核与已失效，保留旧证据。规范文档也执行单写入者、写前重读和基线检查。
