# 从想法到计划，再由证据调整路线

这是 plan 动作模块的操作协议。目录和状态枚举沿用既有规范；此处补足立项前探索、资源取舍和反馈动作，不引入第二套任务系统。

## 1. 新想法先判断归属

先查现有方向、计划、结果及否定证据，再判断：已有任务的细化、现有方案修订、需要先回答的探索问题、独立计划，或新的长期方向。判断依据是目标、完成标准、责任和依赖，不凭方法名称或聊天中“新方向”一词自动建目录。

未成熟想法在 PROJECT 的“待澄清想法”区保留一条轻量记录：稳定想法键、问题、可能影响的决定、来源、相关方向／计划、最小验证动作、预计投入、停止条件、下一次处理触发。具体内容只在此或 PROJECT 映射的既有探索池保存一份；另一处只链接。没有时间依据就写触发条件，不编造截止日。

已有计划内的小探索直接成为该计划任务；独立问题尚不值得承诺执行时留在想法区。用户已明确要求执行且范围足够清楚时，可直接建计划，不强迫先经过一轮收件箱流程。方向本身不需要先有假设，负结果也不自动终止整个方向。

## 2. 立项门槛与停止条件

创建独立 plan 前能回答：要解决什么、为什么现在做、会改变哪个决定、最低需要什么证据、输入和依赖是否可得、工作如何验收、允许投入多少以及何时停止。缺失项分清“探索本来要查明的未知”和“执行前必须满足的条件”；后者未满足时不能把任务标成可开始。

预算按项目实际表达为时间、计算资源、样本、人工或费用。未明确时写待定，不代用户承诺资源。停止条件可以是预算耗尽、关键输入不可得、证据已足够回答问题或前提失效；不能只写“直到得到显著结果”。达到条件时总结已有证据，决定完成、暂缓、取消或提出有理由的范围修订，不无声延长探索。

升级为计划时保存原想法键和来源，想法区仅标去向及链接。合并到已有计划时同样保留去向，避免下次重复立项。暂不做写原因和重审触发；不要把暂不投入解释为科学上已被否定。

## 3. 排序与资源冲突

先找真正可开始的任务，再比较优先级。依次考虑：影响已有结论可信度的核查、解除多个下游阻塞的工作、能区分竞争解释的探索、时间窗口和用户指定的交付、投入与可逆性。记录选择理由，不强制用虚构分数制造精确排名。

区分三种关系：

- 执行依赖：前置证据未通过就不能开始，用 depends_on 表达。
- 资源冲突：争用设备、算力、同一文件写入或研究者注意力，在计划约束和 TASK 接续区中说明安排；不要伪装为科学依赖。
- 生命周期关系：拆分、合并、替代和继承，仅记录前后继，不当成依赖边。

同时保留“当前聊天焦点”和“仍在运行的作业”。切换焦点不自动暂停作业；有空闲算力也不代表研究者能同时解释所有结果。活跃数和解释积压按实际容量评估，提出取舍建议，不自行固定上限或取消已授权工作。

## 4. 结果、判断与下一步的反馈

一次新证据到来，依次核对：事实是否通过检查、与哪条假设或完成标准有关、是否可比较、改变了哪个判断、影响哪些后续计划或采用。运行失败先判断是技术故障还是设计无法执行，不能直接写成假设不成立。

interpret 形成有范围的判断后，plan 将建议映射成明确动作：继续当前任务、修订方案、增加核查、拆出新计划、暂停或结束；保存判断引用和理由。对尚未确认的建议保留建议身份，不把它冒充用户决定。科学结论和已有授权分别核对。

共享证据被纠正时列直接消费者，并沿已登记依赖追踪后续影响；先把受影响完成项或采用标为待复核，保留原历史，不批量改写旧结论。未掌握的消费者写影响范围未知。项目汇总只能在权威记录更新后刷新。

## 5. 交接、体检和归档

恢复只读项目入口、当前焦点、目标计划和最近接续，再沿必要依赖展开。记录读取到的版本／核对时间及尚未核对部分。恢复时优先检查暂停后发生的输入、依赖、方案和判断变化，而非机械执行旧的下一步。

体检除机械脚本外，人工核对：未处理想法是否有去向；活跃计划是否有下一动作；受阻项是否有解除条件和责任；预算或停止条件是否触发；结果是否已进入判断；判断是否落实到任务；完成项是否仍满足验收；索引是否孤立或过期。长期没有变化本身不是自动取消依据，先查为何停止。

完成与归档分开。完成记录按验收关闭；归档只是降低日常视图噪声，保留稳定身份、可达路径、后继关系和证据。默认过滤已完成项即可，不移动文件；确需移动按项目迁移与授权规则执行。

## 6. 三个操作例

- 想试一个新模型：若仍回答原问题且比较条件不变，先在既有计划增加方案或任务；无需新方向。比较目标改变时再评估新 plan。
- 两个计划都等同一预处理产品：只登记一份生产任务和产物，两处引用；任务可依赖明确的验收节点，无需等整个生产计划结束。
- 探索未发现预期效应：证据和检查满足原完成标准即可完成；是否继续投入由判读和预算决定，不能为了“成功”不断换条件。
