# 计划管理资料的进一步阅读与取舍

2026-10-19。参考用户提供的建议汇编（本地归档 `<reference-archive>/…`，公开版不含原文）和 [MADR 模板](https://github.com/adr/madr/blob/main/template/README.md)。本页记录机制判断，不为汇编中的工具功能、排名或星数背书。

| 资料中的思路 | 现有状态与本次处理 | 理由 |
|---|---|---|
| 主线与探索分开 | 保留目标、方向、plan、任务的区别；不增加强制 lines 层 | 一个方向可多 plan，一份 plan 可跨方向 |
| Exploration 先于正式计划 | 补充 INDEX 待澄清想法区、立项门槛和去向引用 | 避免想法丢失，也避免每个念头都建计划 |
| 六层逻辑职责 | 采用职责分离，沿用现有目录 | 逻辑层不等于六套文件或软件 |
| 当前焦点、暂停恢复 | 已有；补充焦点与后台运行区别、前提变化核对 | 切换聊天不是停止分析 |
| 依赖、WIP 和优先级 | 补充执行依赖／资源冲突／生命周期关系，按容量排序 | 固定活跃两三项没有项目依据 |
| 时间盒和停止条件 | 补入计划正文与探索协议 | 防止无限试到满意结果；阈值需项目决定 |
| 结果改变研究路线 | 补充事实→判断→行动→消费者复核 | 结果、判断与任务状态不能混为一谈 |
| Dashboard、NEXT、NOW、MAP | 职责吸收进既有 INDEX／TASK 接续区 | 避免平行维护多个当前状态 |
| Obsidian、任务系统与查询 | 仅作可选派生视图 | 不以插件可用为开工前提，不增加权威源 |
| 每方向独立 Agent | 不默认采用 | 隔离要有上下文、权限或执行需求依据 |
| 完成与 Accepted／Discarded | 不混用 | 阴性结果可以完成，完成不代表采用 |

## MADR 的进一步启发

[分类决定](https://github.com/adr/madr/blob/main/docs/decisions/0010-support-categories.md) 权衡了标签、文件名、目录和编号。借鉴其按作用范围组织与局部身份的思路，继续使用项目／计划已有 decisions；跨范围引用使用完整路径或带项目、计划的身份，不能只写 ADR-001。它的目录方案不用于把研究方向强制变成目录。

[中性论据决定](https://github.com/adr/madr/blob/main/docs/decisions/0014-allow-neutral-arguments.md) 允许中性影响。模板补充有利、不利和中性条件，避免把所有证据强塞进支持／反对二选一。未知影响仍须标未知，中性不等于缺证据。

MADR 完整模板中的决策者、咨询者、知会者，以及 Confirmation 已在上一轮纳入；本轮进一步明确共同责任不能靠填写参与者名单替代，实际落实证据与科学验证仍分开。

## 本轮范围

以上为阅读后落到 skill 的操作规则与模板改进。没有安装资料推荐的工具，没有改实际研究项目，没有增加自动调度器。机械校验器能力不因文档增加而扩展；新增语义要求目前依赖按协议检查。
