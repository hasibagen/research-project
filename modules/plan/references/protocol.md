# 管理协议

## 权威来源

PROJECT 管结构和方向词表；每份 PLAN 的 YAML 头管理计划身份、状态、依赖和 task_files，各 TASK 管任务身份、状态与验收；正文管理目标、设计、验收及修订说明。PROJECT 内计划入口登记各计划，TASK 接续区保存当前任务上下文，LOG 是事件历史。判断与结果通过引用连接，不挤进状态枚举。

PLAN 的“本计划资源与目录”集中维护本计划采用的数据、代码、结果和参考资料入口；PROJECT 继续维护项目共享根，数据产品和 run 保留自己的版本事实。TASK 引用该节，不再独立维护目录总表。路径摘要变更按结构规范同步，校验器通过不证明四类资源已核实。

plan 与 task 使用：未开始、已承诺、进行中、待判断、受阻、待复核、暂缓、完成、取消。新格式任务文件按 PLAN 所在目录解析，必须位于本计划 tasks 目录；每次校验只传一个 project 的 plans 目录。旧内嵌 tasks 与新 task_files 不得并存。

完成时任务全部处置（完成或有原因取消），必需检查通过、引用证据、记录结论／判断位置；科学阴性可以完成。取消／暂缓必须有原因，暂缓附恢复条件。受阻说明阻塞与解除条件；未解决可信度问题转待复核。完成后有新缺陷可转待复核，保留原完成记录与重新打开原因。

依赖使用 plan_id 或 plan_id#task_id；没有 # 表示等待整个计划完成。任务可依赖其他计划或本计划任务；禁止自依赖与环。未完成依赖阻止相关任务开始，确有部分产物可先做时改为依赖明确的已验收任务，写理由，不静默忽略依赖。完成的依赖后续失效，检查消费者并标待复核。

拆分合并记录 predecessor/successor 关系，不把生命周期关系误作执行依赖。方向不由目录名推断，停止范围引用具体计划、输入和评估条件。一次会话可处理多计划，但每条事件明确归属。

## 周期检查与权限

周期检查按项目实际约定，不默认七天审计，也不代表有后台服务。每次管理动作校验涉及计划，并检查直接消费者；结构变更后全量检查。旧计划缺字段列待接入，不编造历史时间和证据。

校验器检查唯一身份、枚举、必填字段、本地引用、依赖存在及环、完成证据、运行中前置条件。它不验证科学结论、Markdown 的全部语义、并发排队、真实超算状态或外部 URL 可用性；不能替代完整审计。它不会写文件或变更计划状态。

宿主任务系统只能作为可选执行视图，接入前验证身份映射、完成回写和退出导出。当前不依赖 pi-tasks，也不自动调用子 agent。任何外部系统更新遵守用户授权。

立项前探索、预算停止、资源冲突、证据反馈和归档按 [探索与反馈协议](exploration.md) 执行；未成熟想法默认记录在 PROJECT 的待澄清区，不另建 INDEX 或新增任务状态枚举。
