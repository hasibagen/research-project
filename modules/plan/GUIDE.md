# 科研方向、计划与进度管理

## 动作架构与结构依赖

本模块负责研究安排与状态变更；写入前读取[文档](../../structures/documents/GUIDE.md)；需要引用运行时加 [结果](../../structures/results/GUIDE.md)，再读项目对应职责区的实际说明。

流程：方向／问题及已有计划 → 区分修订或新计划 → 核对依赖与验收 → 更新唯一状态源。

输出与边界：PLAN、TASK、LOG 及按需决定；运行实体仍留结果根。

具体输入、操作、输出和验收样例见 [EXAMPLE](EXAMPLE.md)。目录及接口约束由结构层维护，下文只规定动作。

负责“探索哪些方向、有哪些 plan、先做什么、做到哪、从哪里继续”。项目架构由对应结构模块规定，创建整理交 [organize](../organize/GUIDE.md)；科学解释交 [interpret](../interpret/GUIDE.md)；执行和交付分别交 [run](../run/GUIDE.md)、[release](../release/GUIDE.md)。本模块不另建一套结果或任务数据库。

## 进入与恢复

先读 PROJECT 的权威路径与计划入口，再读相关 PLAN、TASK 当前接续和 LOG 最近事件。只加载本次相关 plan，不重读整个项目或从聊天猜状态。若旧项目文件布局不同，按已登记映射接入，不强行搬动。

新建或实质修订 PLAN 时，在目标之后建立“本计划资源与目录”集中入口，先核对本计划的数据、代码、结果、参考资料四类资源，再展开方法。遵守 [计划资源规则](../../structures/documents/GUIDE.md#本计划资源与目录)，使用 [PLAN 模板](assets/PLAN.md)。现有目录总表可直接规范化，不额外建立同义文件。读源码或目录只能支持对应核对结论，不能把路径存在写成数据／结果已验收。

方向与计划多对多；方向是研究组织标签，不等于一个目录或一个 plan。每份计划有稳定 plan_id，内部 task_id 以计划为命名空间。先查已有计划和负结果，再判断新想法是现有任务、方案修订、新 plan 或新方向；普通参数尝试不自动新建 plan。

## 固定动作协议

每次变更按“读当前基线 → 定位对象与依赖 → 更新权威计划 → 追加所属日志／决定 → 刷新索引和进度 → 校验 → 写接续位置”执行。写前重读，发现并发变化先合并；不覆盖人工判断。已有授权内推进，不将所有状态修改变成重复审批。

- **创建**：明确目标、探索／确认性质、范围、关联方向、依赖、任务、预算和完成标准；未定假设写未知，不伪造假设。
- **拆分／合并**：保留原 plan_id 与历史；新计划记录 derived_from，旧计划记录 successors 与处置理由。重新挂接任务和依赖，确认没有遗失或双重计数；不删除旧计划。
- **排序**：先处理影响既有结论的核查，再考虑能改变下一步决定的探索、前置条件和成本。明确推荐理由，不仅按最新消息或最好分数排序。
- **切换焦点**：给当前计划留下已做、证据、未做、阻塞与下一动作；加载目标计划并核对依赖，更新 TASK 接续区中的当前重点。切换聊天焦点不自动取消后台作业。
- **暂停／恢复**：暂停写原因、接续点和恢复条件；恢复核对新证据、输入版本及依赖，不能直接沿用过期假设。
- **完成／取消**：完成需要任务验收和证据，不要求假设成立；取消保留原因及已有结果。完成、被采用、阴性结果和运行失败分别表达，不以 Accepted/Discarded 混成一个状态。
- **进度同步**：任务执行成功可转待判断；判读后按完成标准处置。索引和进度从计划派生，不重复手工维护任务状态。共享 run 在多个计划中引用同一事实，不能复制数字形成多份证据。
- **审计**：每次切换／收尾轻检；按项目实际约定周期和重大变更检查孤立计划、引用、依赖环、长期阻塞、未解释积压、完成证据与未登记计划。

活跃计划上限由项目设置，可提出建议但不擅自固定为 2 或 3。超限时说明资源冲突和选择建议，不自动暂停工作。TASK 接续区保留当前焦点和下一动作，不额外增建 NOW／DASHBOARD／NEXT 三套状态。

## 操作依据与校验

读取 [管理协议](references/protocol.md) 的状态与一致性要求；使用 [计划模板](assets/PLAN.md)、[任务模板](assets/TASK.md) 和 [接续模板](assets/handoff.md)。语义与科学设计由 AI／研究者判断，机械错误交 scripts/check_plans.py。脚本只读，使用 conda Python，并传入绝对项目根和计划目录；先运行 --help。

原有 Markdown 没有结构化头时先登记“未结构化／待接入”，不要批量重写历史。新 PLAN 的 YAML 头保存计划状态与 task_files；默认 TASK 的 YAML 头以 tasks 列表保存各任务状态（按需拆出的单任务文件保留单任务头），正文表达执行与验收。旧表格迁入后成为派生视图，不允许两处独立更新。

具体目录按 [项目结构规范](../../structures/documents/GUIDE.md)，安全、备份与终评按 [日常规范](../../docs/daily-operations.md)。缺少终评准入时暂停相关终评，不阻断其他已授权计划。科学判断保留 Hypothesis、Plan、Result、Decision 的区别。

完成一次管理动作后说明：更新了哪个计划、状态依据、受影响依赖、检查结果、当前焦点和下一步。没有写入证据不得宣称进度已同步。原资料与借鉴取舍见 [来源说明](references/sources.md)。

交付 PLAN 时给出可点击的实际 PLAN 绝对路径，并简要指出四类资源入口。结构校验通过之外，还要逐项核对资源表是否具体、可定位、区分实际与拟建；未核对的外部／远端路径如实列出。不能仅汇报更新了多少文件而让用户找不到计划本身。

遇到未成熟想法、立项取舍、资源冲突、停止条件或结果改变后续路线时，读取 [探索与反馈协议](references/exploration.md)。想法先登记去向，任务完成与成果采用分开，停止条件按证据和预算判断。

## 完整工作流

按本模块动作读取 [results-workflow](../../docs/results-workflow.md)。这些文档包含模板、证据位置、输入输出、恢复与验收要求，不能只执行本页摘要便宣称流程完成。

按 [研究原则](../../docs/research-principles.md) 核对当前阶段、接手需求和适用证据声明；已有信息引用原处，不重复填表。
