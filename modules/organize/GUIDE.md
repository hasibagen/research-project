# 创建与整理动作

负责把结构规则落实到新项目或已有职责区，包括创建入口、架构补齐、归属整理和授权迁移。不是周期性全盘清理，不按文件名推定可删除。

## 动作架构与结构依赖

输入：用户目标与范围、真实入口和布局、现有调用与数据来源。
流程：现状核对→选择职责区→目标架构与落点清单→授权范围内实施→校验→切换引用并留接续。
输出：实际架构与区内样例、可解析入口、修改证据和未完成项。

先读 [整体结构](../../structures/project/GUIDE.md) 与 [文件归属](../../structures/project/placement-rules.md)，再读涉及区的结构 GUIDE 和 EXAMPLE。仅建立文档不必加载所有数据／运行规则。

## 创建

1. 区分新项目和给已有项目增加职责区；查已有路径与入口，不建立第二套。
2. 新项目遵守用户对代码／科研类型和 jj 初始化选择的约定。现有 skill 重构不属于新科研项目初始化。
3. 给出完整目标树，注明本次会实际创建的部分；单模态数据直接 raw/interim，多模态才分模态。
4. 实例化根入口和必要文档；每个实际创建区写明内部架构与具体样例。生成器只创建已支持的文档骨架，不能宣称它已生成科学代码、数据或 run。
5. 确认生成内容、链接与配置生效情况，把仍需用户提供的科学事实留待核对。

## 整理与迁移

用 [整理方案模板](../../assets/templates/structure-adoption-plan.md) 记录现状、目标和逐项映射。优先解决职责和权威入口，再决定是否需要移动；只读接入不执行迁移。

列每项材料的源／目标绝对路径、原因、来源身份、消费者、活动进程、检查与恢复。数据和 run 不因计划变化搬动。正在使用的输入输出和 tmp 排除出搬迁批次。结果归档仍在登记结果根内部。

迁移保存原内容与身份，核对清单、大小、必要内容哈希及引用后切换入口；源文件处置按实际授权，不因校验通过删除。文档重构可保留旧入口为跳转，但当前正文只维护一份；旧全文作为明确历史快照保存。

## 收尾

核对根入口→区入口→对象及来源链路；同步 AGENTS、PROJECT 和受影响 README。已完成、待核对、尚未迁移分别记录。更新所属 TASK 和 LOG，不能仅凭新树写“整理完成”。

具体新建与旧项目整理样例见 [EXAMPLE](EXAMPLE.md)。
