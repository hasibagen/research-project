# 科研交付与溯源

## 动作架构与结构依赖

本模块负责固定采用与交付；写入前读取[交付](../../structures/delivery/GUIDE.md)、[结果](../../structures/results/GUIDE.md)；纳入数据时加 [数据](../../structures/data/GUIDE.md)，再读项目对应职责区的实际说明。

流程：明确采用范围 → 核对来源与科学检查 → 固定 DELIVERY → 按需打包／检查 → 记录实际交付。

输出与边界：采用映射、固定包及检查；外发依实际授权，归档仍按结果归属。

具体输入、操作、输出和验收样例见 [EXAMPLE](EXAMPLE.md)。目录及接口约束由结构层维护，下文只规定动作。

先明确采用哪些方案、运行、结果行及图表，检查材料身份、许可与访问条件。基于实际来源记录导出 RO-Crate；不得从空模板宣称合规。基础标准、profile、生成器与校验器版本分别记录。

分别报告元数据符合性、文件完整性、可取回性、计算复现和科学检查。基础 RO-Crate 通过不代表 Workflow Run profile 通过。需要工作流执行语义时按官方 profile 映射并实际验证，不臆造必需字段。

用公共程序导出到新的目录；保留检查报告和限制。准备包不等于上传，发布仍遵守用户明确授权。材料可留在外部受控位置，但引用必须可解析；导出不得泄露真实个人数据或凭据。引擎缓存和可视化工具不是证据唯一来源。

交付前必读 [日常操作规范](../../docs/daily-operations.md)。论文采用须代码可追溯、验证方案完整、无影响结论的未解决疑点，并核对独立复算与产物过期状态。输出采用映射，未就绪结果保持探索身份。

核对发布口、仓口、超算口与 AI 口的适用检查：naming/ 姓名映射永不入仓或上超算，研究包与日志不得泄露身份。论文级脱敏小件随获授权仓保存；原始数据与关键证据保留第二介质副本及校验记录。不能以 RO-Crate 校验成功代替安全、备份或科学就绪检查。

## 完整工作流

按本模块动作读取 [results-workflow](../../docs/results-workflow.md)。这些文档包含模板、证据位置、输入输出、恢复与验收要求，不能只执行本页摘要便宣称流程完成。

按 [研究原则](../../docs/research-principles.md) 核对当前阶段、接手需求和适用证据声明；已有信息引用原处，不重复填表。

交付事件追加计划 LOG；正式固定采用范围时按需生成计划内 DELIVERY.md。检查结果写 TASK 或引用报告，不默认创建 releases／audits 目录。
